# 21_OV5640_SFP480p_test 修改说明

由 `10_HDMI_DDR3_OV5640_test` 修改而来。当前版本（Rev 3.0）：

- **OV5640 改为 640×480@60fps（480p60）**，两颗摄像头同时启用；
- **HDMI 双摄同屏输出**：左半屏 = CMOS1，右半屏 = CMOS2，720p30 显示；
- **SFP0 光纤输出链路已注释保留**（随时可恢复，见第七节）。

> 早期版本（Rev 2.0）曾实现"CMOS1 → SFP0 光纤单路输出"，相关代码与协议规格完整保留在源码注释和本文档第六节，供后续恢复光纤输出或开发接收端使用。

## 一、视频通路（当前版本）

```
CMOS1 (640x480 ~60fps RGB565 DVP, PCLK=84MHz) ─┐
                                               ├─ cam2_merge 逐行拼接 (1280x480@60)
CMOS2 (640x480 ~60fps RGB565 DVP, PCLK=84MHz) ─┘        │
                                                        v
              fram_buf (DDR3 行缓存, H_NUM=1280, V_NUM=480)
                                                        │
              sync_vg 720p30 读出时序 (pix_clk=37.125MHz)
                                                        v
              MS7210 HDMI 输出: 1280x720 画面, 上部 480 行为双摄并排图像
              (左 640 列 = CMOS1, 右 640 列 = CMOS2, 下方留黑边)
```

双摄拼接原理（`cam2_merge.v`）：
- 两颗摄像头时钟独立（各自晶振），B 路（CMOS2）经异步 FIFO（格雷码指针，只投递有效像素）进入 A 路（CMOS1）42MHz 时钟域；
- A/B 各用两块 640×16 行缓存乒乓；每合成行 = A 行 640 拍 + 行间隙 + B 行 640 拍，行内 de 连续、行间有间隙（满足 fram_buf 写侧 x_cnt/y_cnt 要求）；
- A 的行周期 1000 拍（有效 640），合成行耗 1284 拍，A/B 行在另一页缓存中提前就绪，稳态无缝不丢行；
- 漂移自恢复：B 每帧只投递前 480 个有效行，B 偏快丢行、偏慢等待。

帧率：摄像头 ≈59.6fps，显示 30Hz（720p30，与原 demo 相同机制，写快读慢，"最新帧胜出"）。

## 三、OV5640 寄存器改动（reg_config.v，两颗摄像头共用同一配置）

保持 PLL/时钟类寄存器（PCLK=84MHz）与全部画质查表不变，仅改时序项：

| 寄存器 | 原值 | 新值 | 说明 |
|---|---|---|---|
| 0x3800/0x3801 | 0x00,0x00 | **0x02,0xA0** | 裁剪 X 起点 672 |
| 0x3802/0x3803 | 0x00,0xFA | **0x01,0xEC** | 裁剪 Y 起点 492 |
| 0x3804/0x3805 | 0x0A,0x3F | **0x07,0x9F** | X 终点 1951（窗口宽 1280） |
| 0x3806/0x3807 | 0x06,0xA9 | **0x05,0xAB** | Y 终点 1451（窗口高 960） |
| 0x3808/0x3809 | 0x05,0x00 | **0x02,0x80** | 输出行长 640 |
| 0x380A/0x380B | 0x02,0xD0 | **0x01,0xE0** | 输出行数 480 |
| 0x380C/0x380D | 0x07,0x64 | **0x07,0xD0** | HTS=2000 |
| 0x380E/0x380F | 0x02,0xE4 | **0x02,0xC1** | VTS=705 |
| 0x3811/0x3813 | 0x10/0x04 | **0x00/0x00** | ISP 窗口偏移清零 |
| 0x3A03 | 0xE0 | **0xAC** | 最大曝光 684 < VTS |
| 0x3A15 | 0xE0 | **0xAC** | 抗闪最大曝光同步下调 |

原理：居中裁剪 1280×960（保持 4:3），保留 0x3814/0x3815=0x31 的 2:1 抽样，精确得到 640×480，无需 ISP 缩放。帧率 = 84MHz/(2000×705) ≈ 59.6fps。

**时序修复要点**：摄像头数据引脚到 cam2_merge 内部 RAM 写口为最小路径，相对 42MHz 门控时钟的大延迟会产生 hold 违例——已在 merge 内部对 A/B 输入各加一级寄存（RGB565 通道重排同步移入该级，A/B 等延迟），修复后全编译 **0 时序违例**。

**管脚电压调整**：SFP0_TX_DIS（H12）与状态脚 A2/A3/B2/B3/C5 同一 bank，08 例程为 3.3V 而原 10 工程标 1.2V，混用报 bank VCCIO 冲突。已将 A2/A3/B2/B3/C5（均为 LED/状态输出）统一为 3.3V/LVCMOS33/drive 8。

## 六、（保留）SFP0 光纤输出协议规格 — 供恢复光口/开发接收端

HSST CH2（SFP0），5Gbps，8B10B，fabric 接口 32bit@125MHz（时钟 = `o_p_clk2core_tx_2`）。字节序：`i_txd_2[7:0]` 为线上第一字节；`txk[n]` 为对应字节 K 码标志。接收端以 K28.5 逗号字对齐，按 `rxk` 区分字型：

1. **数据字**（`rxk==4'b0000`）＝ 2 个有效像素：`txd={pix1[15:0],pix0[15:0]}`，byte0/1=先发像素 pix0（RGB565），byte2/3=pix1。
2. **控制字**（`rxk==4'b1001`）＝ 空闲/状态：`txd={8'hBC,{de,hs,vs,5'b0},8'h28,8'hBC}`，线序 K28.5→D28.2（满足 GE 模式 CTC skip）→状态字节→K28.5。

板上事实：SFP0 = HSST_88_340 quad 的 CH2（TX=B14/A14，RX=D13/C13，TX_DIS=H12），CH3=SFP1，CH0/CH1 为 PCIe；CH2/CH3 为独立通道（`BYPASS_BONDING=TRUE`）。恢复方法：取消顶层 `SFP0 光纤输出` 注释块与对应端口注释、取消 `.fdc` 中 HSST/SFP 约束行注释、重新编译即可（IP 文件与登记均保持）。
