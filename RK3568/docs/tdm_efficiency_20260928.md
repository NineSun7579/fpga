# YOLO 模型轮换效率实测（RK3568）

## 测试口径

板端隔离构建 `/userdata/linaro/detview-tdm-build-20260928/detview`，输入为循环的 640×480、约 30 fps 视频文件；窗口 20 秒，按每次推理完成的单调时钟计算稳态吞吐。NPU 与 DDR governor 均为 `performance`。每组仅运行一个 `detview` 实例；未使用 PCIe 摄像头，因为当前 FPGA 位流只枚举 64 KiB BAR0，驱动未绑定。正式 `/root/npu/detview/detview` 未替换。

| 配置 | 总推理吞吐 | 各模型吞吐 | 单次模型耗时均值 |
| --- | ---: | --- | --- |
| zebra merged-v3 rm8 单跑 | 23.76 次/秒 | zebra 23.76 | 39.47 ms |
| TT100K anneal-c12 单跑 | 17.55 次/秒 | TT100K 17.55 | 55.16 ms |
| zebra raw-dfl6 rm16 单跑 | 23.47 次/秒 | zebra rm16 23.47 | 40.24 ms |
| vehicle raw-dfl6 单跑 | 23.77 次/秒 | vehicle 23.77 | 39.55 ms |
| zebra rm8 + TT100K 轮换 | 19.88 次/秒 | 各约 9.94–9.95 | 39.17 / 55.98 ms |
| 上述四款轮换 | 21.44 次/秒 | 各约 5.36–5.38 | 38.26 / 56.20 / 40.68 / 40.09 ms |

两款公平轮换的理想吞吐 `2/(1/23.76 + 1/17.55) = 20.19` 次/秒；实际 `19.88/20.19 = 98.47%`。四款的理想吞吐 `4/(1/23.76 + 1/17.55 + 1/23.47 + 1/23.77) = 21.77` 次/秒；实际 `21.44/21.77 = 98.49%`。因此轮换本身约损失 **1.5%**，上下文缓存避免了逐帧模型加载。

与 zebra rm8 单跑相比，两款轮换的总吞吐下降 **16.3%**；zebra 自身更新率由 23.76 降至 9.94 次/秒，下降 **58.2%**。TT100K 由 17.55 降至 9.95 次/秒，下降 **43.3%**。四款轮换中每款约 5.36 次/秒，zebra rm8 比单跑下降 **77.4%**。视频解码仍约 30 fps；两款配置每秒处理约 19.88 帧（66%），四款约 21.44 帧（71%），其余帧按最新帧单槽设计跳过，不会排队重播。

这些数值是**推理完成率**，不是四路 PCIe 采集或屏幕呈现帧率。静态画面与视频模式没有覆盖真实 DMA、相机帧标签和四路拼图竞争；恢复正确位流后须在同样模型组合下补测实际画面帧率与每模型结果时效。
