# 六路四方位环视标定指南

本指南由你执行标定；当前工具仅完成软件和未标定预览，未替你填写测量参数。先退出占用PCIe的detview，再启动独立环视工具。

## 1. 明确摄像头对应关系

| 输入 | 模块 | 方向 | 未做双目融合时的使用方式 |
|---|---|---|---|
| C1、C2 | 同向前双目 | 同朝前，默认0° | 优先C1，C2作新帧备用 |
| C3 | 左 | 默认−90° | 使用C3 |
| C4 | 右 | 默认+90° | 使用C4 |
| C5、C6 | 同向后双目 | 同朝后，默认180° | 优先C5，C6作新帧备用 |

双目左右眼没有自动扩大视野。每眼仍要单独标定镜头和地面映射，因为两眼有基线、畸变和安装误差。当前工具不计算双目深度，也不直接叠加两眼；R/T和硬件同步标定不是当前单眼备用环视的前提，但以后要做双目深度时必需。

C5目前只收到静态帧，先修复其持续出图再标定它；这期间C6可以承担后方预览。不要拿一张冻结画面冒充多姿态标定图。

## 2. 启动、保存和回退

```sh
sudo -E bash /userdata/surround360/run_surround360.sh
```

`1`环绕，`2`俯视，`Tab`切换；鼠标拖动转向，滚轮调整视场；`C`打开标定面板。面板保存路径为`/userdata/surround360/calibration.json`。

先备份配置：

```sh
sudo cp /userdata/surround360/calibration.json /userdata/surround360/calibration.before_manual.json
```

面板中的导入、恢复预览参数和编辑先作用于草稿；“保存并应用”通过验证后写入文件并更新视图。失败时保留原配置。恢复旧配置后重启工具即可回退。退出环视后恢复detview：

```sh
sudo -E bash /userdata/surround360/restore_detview.sh
```

## 3. 每眼镜头内参和畸变

准备平整棋盘格，例如9×6**内角点**，即10×7格子。测量每格实际边长，例如20mm；格子数量与内角点数量不要混淆。固定焦距、分辨率和镜头，不在拍摄过程中改变对焦或裁剪。

每眼采集至少15–25张有效图片，棋盘格分布在中央、四角和边缘，距离、倾角不同，避免模糊、过曝、棋盘格弯曲和角点被遮住。不要把同一静止画面重复保存几十次。

打开`C`面板时冻结一组当前图片；“采集六路标定图”保存的是打开面板时的图片。每次改变棋盘格姿态后**关闭并重新打开面板**再采集。图片位于配置目录的`calibration_captures/<时间>/C1.png…C6.png`，`manifest.json`记录各路时间和缺失状态。该功能不保证六路曝光同步。

将每眼的图片分别整理到一个目录。用OpenCV针孔`calibrateCamera`，或者确认是鱼眼后用`fisheye.calibrate`。不能仅凭480p分辨率判断镜头模型。得到：

- `K`：3×3内参矩阵，按行展开为9个数，包含fx/fy/cx/cy。
- `D`：针孔4/5/8项，鱼眼4项，必须保留OpenCV系数顺序。
- 标定时分辨率必须640×480，与工具输入一致。其他尺寸须按实际缩放/裁剪关系转换K，不能直接复制。

`calibrate_intrinsics.py`可帮你对整理好的棋盘格照片调用OpenCV，输出单眼JSON和逐图误差；它不会自动给板端配置打“已标定”标记。例子：

可以在电脑上运行，无需占用3568采集设备；Python环境需安装`numpy`和OpenCV（例如`python3 -m pip install numpy opencv-python`）。

```sh
python3 calibrate_intrinsics.py --images C1_photos --cols 9 --rows 6 \
  --square-mm 20 --lens pinhole --output C1_intrinsics.json
```

鱼眼使用`--lens fisheye`。检查成功识别数量、逐图误差和校正后直线，重投影误差越小越好，但低误差不能代替边缘覆盖和独立图片验证。删除明显模糊或错误角点图片后重新计算，不要为了数字漂亮只留下中央同角度图片。

把结果写入该眼配置项：`K`、`D`、`distortionCount`、`lens`（`pinhole`或`fisheye`），检查后再设`intrinsicCalibrated: true`。`D`在工具配置里保存8项；不足8项的尾部填0，并用`distortionCount`记录实际项数。导入整个配置文件，不是只导入单眼结果JSON。

标定面板会使用这些内参显示校正后的图片，地面源点应在**校正图**上选择。

## 4. 环绕方向和视场角

在车辆/平台周围放置可识别的远处标记，逐个方向旋转视图，确认没有左右镜像或倒置。面板可调`yaw`、`pitch`、`roll`和未标定时使用的水平FOV。

前双目同朝前、后双目同朝后；不能通过给两眼相反yaw角来制造覆盖。允许用实测小角度修正真实安装误差。镜头内参已标定后，实际投影使用K/D，FOV字段主要服务未标定估计，不要靠随意改FOV掩盖错误内参。

相邻**方位**必须有实际重叠：前与左/右，后与左/右。没有重叠时不能靠羽化补出真实图像；应调整安装或接受缺失区域。方向参数确认后才勾选方向已测量。近物接缝仍可能重影，因为摄像头有不同位置，单纯旋转投影不消除视差。

## 5. 俯视地面四点

在平台周围同一平面上放标记，最好用卷尺量出各点相对平台中心的位置。每路选四个不共线、分布充分的地面点；点的位置要在校正图上清晰可见。避开轮胎、墙、桌面、人物和其他竖直物体。

面板左侧四点来自该眼校正图，右侧四点来自所有摄像头共用的地面画布。编号要一一对应，并沿四边形顺序排列，不交叉：通常为远左、远右、近右、近左。

512×512画布中心是(256,256)，前方朝上，右方朝右。若选固定每米`s`像素，地面点相对中心为`x`米向右、`y`米向前，则：

```text
目标X = 256 + s × x
目标Y = 256 − s × y
```

六路必须使用同一中心、方向和比例。当前车体图标/中心遮罩仅为显示占位，不代表真实车身尺寸；不要把图标边缘直接当作卷尺原点。目标点必须落在画布内。前后双目两眼分别选择自己的源点，但映射到同一组真实地面坐标，才能在备用切换时保持一致。

拖动完成并根据实测对应关系验证后，勾选地面对应点已测量，再保存应用。未测量的默认四象限区域只供预览，不是标定。

## 6. 验收与常见问题

用**没有参与拟合**的地面点检查俯视位置、方位、比例和跨摄像头接缝；不要只检查四个拟合点。正常目标应能从前方移动到左/右、再到后方，地面边界不会出现明显跳变。分别检查前/后备用眼，不能只标定主眼。

| 现象 | 优先检查 |
|---|---|
| 两图交界重影 | 镜头参数、地面点、方位、实际重叠；近物视差和不同步不能只靠羽化解决 |
| 地面拉歪或比例不一 | 源点是否在校正图、对应顺序是否一致、目标坐标是否共用比例 |
| 人物/柱子被拉长 | 地面投影只能对地面成立，这是平面模型限制 |
| 后方主眼停止但仍有画面 | 可能已使用同向C6备用，查看输入状态和选用说明 |
| 输入停止/缺图 | 先看各路帧率；没有实时输入时不要继续标定 |
| 保存失败 | 检查四点凸形、非共线、画布边界、K/D和目录权限 |

工具的“已标定”来自你确认的配置标记，不是自动精度认证。全部六眼完成镜头参数和相关方位/地面配置后，警告才会消失；保持尚未完成的标记为false。现有工具不自动做双目深度、硬件曝光同步或真实三维重建。
