# 独立工具的位置与共享板端使用

源码工作区：`/userdata/linaro/surround360-work/`。
安装程序：`/userdata/surround360/surround360`。
配置：`/userdata/surround360/calibration.json`。
证据：`/userdata/surround360/evidence/`；合成显示验证保存在`synthetic/`，与真实采集分开。

```sh
# 先正常退出 detview/camview，使设备无人使用
sudo -E bash /userdata/surround360/run_surround360.sh
# 退出环视后恢复 detview
sudo -E bash /userdata/surround360/restore_detview.sh
```

环视程序独立于现有detview的源码、模型和程序。两个真实采集应用不能同时打开现有驱动，打开动作会重置DMA状态。测试脚本使用有时限的实例，并在退出后恢复前一个查看器的命令行。上机前重新查询当时拥有者，不依赖历史PID。

最终布局是四方位，而非六个独立朝向：前双目C1/C2同为0°，左C3为−90°，右C4为90°，后双目C5/C6同为180°。前后各选一眼，另一眼用作新帧备用。安装前保留旧的未标定配置，并生成更正后的默认配置；已经实测标定的文件不得自动覆盖。

配置没有实际标定时两种视图都显示未标定提示；初始配置明确保留false标定标记。截图只是视觉记录，不证明镜头或地面几何精度。C5/C6为同向后双目；C5没有新帧时选C6作为后方输入，两路均停止才显示后方缺失。

GPU环绕不生成CPU全景帧；它直接采样六路640×480纹理，按虚拟相机角度投影并融合。CPU地面投影复用缓存映射，运行在后台。工具不调用NPU。
环绕投影先在640×480 GPU帧缓冲内完成，再用单张纹理放大到显示器；避免在1080p的每个像素上重复计算六路投影。

板端重启后如果MSI/DMA超时，原detview也可能不可用。现有仓库的PCIe重扫/原驱动重载流程曾恢复过输入，但不保证消除所有硬件状态异常；恢复失败时记录实际错误，不以合成画面假装六路实时采集正常。

开发期间的几次重启已由用户确认是主动重启，不作为程序崩溃或编译失败证据。
