# 方案：定期 YOLO + 模板匹配做识别与跟踪（2026-09-30，仅方案）

## 0. 为什么需要这个架构（用今天的实测数据说话）

- 单次 YOLO 应用内耗时（V8，6 路并发）：**33–36 ms**；轮换两款时每款只有 ~11–13 fps。
- 若每路每帧都跑 YOLO：4 路 × 33 ms = 132 ms/帧 → **整体 7–8 fps**，不可行。
- 但**显示路径有余量**（26 fps、`paintGL` 17–24 ms），**CPU 也有余量**（DFL 解码仅 1.1 ms、prep 已优化到 0）。
- 逐层分析还表明：**NPU 是 DDR 带宽受限**（V8/V9 层数相近但访存差 22% → 耗时差 28%），继续压模型收益有限。

结论：把 **NPU 当"定期重检测器"**（低频、高精度），把 **模板匹配当"帧间跟踪器"**（高频、极廉价），
两者互补：跟踪提供每帧平滑框与 ID，重检测提供类别与纠偏。

## 1. 总体架构

```
每路相机（25 fps）
  ├─ 帧间：模板匹配跟踪（CPU 或 FPGA）→ 每帧输出 {id, box, class, score}
  └─ 定期：YOLO 重检测（NPU，错峰调度）→ 刷新/新建/删除 track
                     ↓
               Track Manager（每路一份 + 全局融合）
                     ↓
              显示叠加（每帧框+ID）/ 上报（事件、统计）
```

三种数据流：

| 流 | 频率 | 执行体 | 作用 |
|---|---|---|---|
| 模板匹配 | 每帧（25 Hz/路） | CPU 小核循环 或 FPGA | 更新位置、维持 ID、给出相似度 |
| YOLO 重检测 | 每路 1–5 Hz，错峰 | NPU（RKNN） | 类别、纠偏、新建/删除 track |
| 模板库比对 | 每 N 帧或事件触发 | CPU 或 FPGA | 识别"这是不是已知目标"（白板/车辆/标志等） |

## 2. 跟踪器设计（核心）

### 2.1 模板与搜索

- **模板**：重检测命中后，从该框内取 **1–3 个尺度**的灰度小块（如 24×24、32×32、48×48），
  存 **归一化** 版本（减均值除标准差）→ 抗亮度变化。
- **搜索**：在上一帧位置周围开窗 `±(0.5w, 0.5h)`（可加运动预测：`v = p_t − p_{t−1}` 外推），
  **金字塔粗到细**：先在 1/4 尺度粗搜（步长 4），再在最优邻域 1:1 精搜（步长 1）。
- **匹配度量**：
  - CPU 首选 **NCC**（归一化互相关，抗增益/偏置）；实测可在 ROI 上做 **SAD 预筛**再 NCC 精算。
  - FPGA 首选 **SAD/SSD**（无需归一化、乘法器少），亮度漂移用 **均值归一化模板**（每帧对 ROI 减均值）补偿。
- **代价估算**（4 路 × 8 track）：1/4 尺度粗搜 24×24 窗口内 ~576 点 + 1:1 精搜 9×9=81 点
  → ≈ 657 点/模板/帧 → 4×8×657 ≈ 21k 点/帧 → **CPU < 0.2 ms**，完全可承受；FPGA 更无压力。

### 2.2 更新与失效

- 匹配成功（NCC ≥ τ_hi，如 0.7）：更新框与模板（**指数滑动更新**，`T ← 0.8T + 0.2T_new`，防漂移）。
- 匹配弱（τ_lo ≤ NCC < τ_hi，如 0.4–0.7）：只更新位置，**不更新模板**，`weak++`。
- 匹配失败或 `weak` 连续超限：标为 `lost`，保留预测外推 ≤ K 帧（如 5），仍失败则删除。
- 模板更新必须**限制频率**（如每 3 帧一次），否则会累积漂移。

### 2.3 尺度与形变

- 尺度：多尺度模板（上表 3 档），或每帧用当前框尺寸重采样模板；
- 快速形变（如白板翻转、行人转身）：靠 **定期 YOLO 重检测**纠正（见 §3）；
- 强旋转场景（车牌、标志）：本方案不追求旋转不变，靠重检测兜底。

## 3. 重检测调度（把 NPU 用在刀刃上）

1. **错峰**：4 路轮流检测，单路间隔 `T_cam`（如 400 ms），任意时刻 NPU 只跑一路 → 每路 2.5 Hz，NPU 占用 ~8%。
2. **自适应触发**（省 NPU）：
   - 场景静止（匹配分数高、框几乎不动）→ 拉长 `T_cam`（如 1–2 s）；
   - 出现新运动/失配 → 立即重检测该路；
   - track 数变化、模板分数下降 → 缩短 `T_cam`。
3. **多模型轮换**：保留现有 detview 的 2–4 款模型轮换机制（白板/斑马线/车辆/标志），
   与"每路重检测"正交——同一时刻只跑一个 (model, camera) 组合。
4. **预算上限**：给定 NPU 目标占用（如 30%），调度器按"上次耗时 × 队列长度"动态调整 `T_cam`，避免积压。

## 4. 识别（不只是跟踪）

- **类别**来自最近一次 YOLO 重检测，track 全程沿用；
- **身份**来自模板库比对：维护一个"已知目标模板库"（如白板目标、常见车辆、交通标志），
  每 N 帧或 track 新建时做一次**模板库全比对**（同样 NCC/SAD）→ 命中则给 track 打 `known_id`；
- **事件**：track 进入/离开指定区域（ROI 多边形）、停留超时、known_id 命中 → 触发上报（日志/HTTP/串口）。

## 5. 落地在 FPGA（可选但推荐，规模化关键）

CPU 方案已够 4 路 × 8 track；若要做到 **6 路 × 20+ track** 或释放 CPU 给其它任务，把匹配放进 RTL：

- **接口草案**（挂在现有相机 DDR 通路旁，不占用 PCIe 主通路）：
  - `TPL_BASE/TPL_LEN`：模板在 DDR 的地址（灰度、8 bit、最多 3 档尺度）；
  - `ROI_BASE/W/H`：搜索窗（来自当前帧的 DDR 乒乓缓冲）；
  - `CFG`：尺度、步长、阈值、最大结果数；
  - `START` / `DONE` / `CNT`；结果 FIFO：`{dx, dy, score}`（或 top-1）；
  - 中断：复用现有 MSI（`pango_irq_handler` 已有 3 条通道，可扩一条 "match done"）。
- **实现要点**：SAD 阵列（如 16×16 并行）+ 行缓冲，读 ROI 用突发读；单次匹配 < 10 µs 量级；
  亮度漂移用"ROI 行均值"在线补偿（每行一个减法）。
- **驱动**：新增一个 ioctl（`PCI_MATCH_CMD`）+ 结果读回，或复用现有 DMA 读回结果区。
- **风险**：DDR 争抢（NPU 已带宽受限）→ 匹配引擎的读带宽要限速/加 QoS，或只读 1/2 下采样 ROI。

## 6. 分阶段实施

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 | Track Manager + CPU NCC 匹配（单路 C1，只跟踪 YOLO 已检出的框） | 跟踪耗时 <0.3 ms/帧/路；框抖动（IoU 波动）比纯 YOLO 明显下降 |
| P1 | 自适应调度（错峰 + 静止拉长间隔） | 每路重检测 1–5 Hz 可调；NPU 占用 <30%；整体显示不掉帧 |
| P2 | 4 路并行 + HUD 显示 ID/轨迹 | 4 路 × 8 track 稳定；ID switch 率 <5%/分钟 |
| P3 | 模板库 + known_id + 事件上报 | 已知目标识别率与误报率达标（按业务定义） |
| P4 | FPGA 匹配引擎（RTL + 驱动 ioctl） | 6 路 × 20 track，CPU 占用不升反降 |

## 7. 与现有代码的衔接点

- **采集/显示**：不动（6 路 3×2、RGB565 合成、GL 显示）。
- **推理线程**：从"按相机帧率提交"改为"由调度器触发"（`setInferPane` 已有该钩子，改成带节流/触发的提交即可）。
- **检测结果**：`detectionsReady` 后先进 Track Manager，再投给显示；框标签增加 `#id` 与 `known_id`。
- **观测**：沿用 `DET_BENCH`（分段计时）+ `[panes]`/`[stats]`，新增 `[track]` 行（track 数、匹配耗时、重检测间隔）。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 模板漂移累积 | 限制模板更新频率 + 滑动平均 + 定期 YOLO 纠偏 |
| 遮挡/消失 | 分数衰减 + 预测外推 K 帧 + 删除后允许同位置重建（避免 ID 复用错乱：ID 只增不复用） |
| 光照/自动曝光变化 | NCC 或均值归一化；FPGA 用行均值补偿 |
| CPU 已较满（相机+显示+解码） | 匹配限定小窗口 + 1/4 尺度预筛；或转 FPGA |
| DDR 带宽与 NPU 争抢 | 匹配只读下采样 ROI；限制并发匹配数；给 NPU 优先 |
| 多路同目标重复上报 | 按相机标定做位置融合（同一时刻多路命中且位置一致 → 合并） |

## 9. 一句话结论

**YOLO 负责"看清是什么"，模板匹配负责"每帧都在哪"**：NPU 从每帧满负荷降到 1–5 Hz 错峰，
显示与跟踪仍保持 25 fps，识别能力靠模板库补齐；规模化（6 路 × 20 track）时把匹配下沉到 FPGA。
