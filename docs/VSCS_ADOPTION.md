## 新增或修改 RTL 的最低要求

- 文件和模块注释说明用途、职责边界和最重要的外部约束。
- 非显然接口说明极性、目标时钟域、有效周期、延迟、背压或错误行为。
- 每条 CDC 先分类，再记录源域、目标域、机制、延迟、事件间隔、复位行为和验证证据。
- 每个时钟域记录复位极性、断言/释放方式和目标域；异步复位必须相对目标时钟同步释放。
- FSM 记录类型、输出时序、编码策略和非法状态策略。
- Verilog-2001 组合过程使用 `always @*`，时序过程使用非阻塞赋值，组合过程使用阻塞赋值。
- 不写作者、修改日期或文件内修订历史；这些信息以 Git 为事实源。
- 不用注释宣称“消除亚稳态”“保证无毛刺”“绝不会丢失”等未经验证的绝对结论。
- 关键假设至少关联 assertion、测试、约束、工具报告或经批准的人工分析之一。

## 自动检查策略

第一阶段仅对本次新增或修改的手写 RTL 启用强制检查，避免厂商生成文件造成大量不可操作告警。后续逐步加入：

1. UTF-8、危险绝对表述、普通 `// @brief`、手写修订历史等低误报文本检查。
2. Verilog/SystemVerilog lint、位宽、隐式网络、锁存和多驱动检查。
3. CDC/RDC、综合属性、STA 和 Doxygen 警告门禁。

任何偏离必须记录适用文件、规范条款、技术理由、风险、补偿验证和重新评审条件。
