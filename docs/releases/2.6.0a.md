# FPGA 2.6.0a

本版本同步 FPGA RTL、PDS 工程、仿真用例、构建/烧录脚本及 RK3568 配套显示代码，并保留 GitHub main 已有更新。主要修复六路视频中的 CAM5 停帧及显示拼接问题，归档显示延迟优化和硬件卸载候选方案。单个文件超过 100 MB 的内容不上传。

## 修复与改进

- **CAM5 空闲捕获恢复**：当捕获元数据残留 complete/bad、控制器空闲且没有有效命令时，连续确认 8 个周期后通过既有局部 flush 恢复后续帧入口；活跃 AXI 命令保留原有所有权与完成流程。
- **六路显示拼接**：归档旧版 GPU 查看器的行跨度与双缓冲修复于 `fpga/detview_legacy_cam5/src/main.cpp`；主 `detview_tdm` 保留远端升级后的完整查看器并新增每路真实交付帧累计数 `gen`，辅助识别停帧和缓存帧率误判。
- **完整 detview 显示调度**：归档 Qt 更新等待、HUD 重绘和上传缓冲优化，以及对应的完整源代码、补丁和验收资料；保留多模型、时序过滤、跟踪、双目和标定功能。
- **绘制前读取最新帧**：归档 late-latch 实现、构建及 A/B/B/A 对照资料。`DETVIEW_LATE_LATCH=0` 可关闭该优化；正式对照中，各路 DMA 返回至 GL 绘制返回的平均帧龄降低约 9.25～12.58 ms，YOLO 完成率约 3.84 次/秒。
- **工程与验证资产**：补充相机、SFP/HSST、DMA 恢复、显示缩放和硬件卸载相关 RTL、工程配置、测试、脚本及版本快照。归档 DMA-BUF / RKNN 共享输入、六路缩略图与批量/后台处理候选方案，其验收状态以各目录报告为准。

## 纳入的远端更新

相对于 `Release-2.4.0ab`，本版本同时保留 main 已有的 50K HDMI 切换 RTL/IP/约束、仿真与烧录资料，RK3568 MVP-R1 INT8 模型及阈值绑定、时序框确认、车辆模板跟踪、480p 视频调试，以及独立四方向 surround360 查看器与标定说明。

## 已记录的验证

- CAM5 厂商 FIFO 仿真通过：恢复后的 12 帧逐像素、标签及 bank 比较通过，AW/B 均为 1680；正常完成/SOF 的 153 个相位与基线一致。
- 本次发布前在独立目录重新运行 CAM5 厂商 FIFO 回归，通过 12 帧恢复检查，AW/B 均为 1680，日志零错误。
- CAM5 独立 PDS 构建记录为 `All Constraints Met`；JTAG 配置成功，SPI Flash 编程及读回校验成功。
- CAM5 修复后的六路视频与 RK3568 RKNN NPU 连续 180 秒验收记录通过：C5 交付帧数从 1603 增至 4330，各路帧数递增，DMA error 均为 0。
- 完整 detview 显示优化的约 91 秒记录中，窗口换帧约 34.17 fps；每路新画面上传速率约为 31.81 / 31.63 / 23.40 / 23.67 / 29.74 / 29.37 fps，DMA 错误、unstable 和推理失败均为 0。
- late-latch 的显示 ownership/config、vision 与 MVP-R1 解码自检日志通过。上述运行数据来自归档验证记录，本次发布未重新上板验收。

## 限制与使用说明

- CAM5 残留元数据导致无法恢复的缺口已通过仿真确认；最初板端如何进入该状态尚未证实，不能将其称为已证明的同周期竞态修复。
- SPI Flash 实际断电重启加载尚未测试。部分回归仍有独立超时记录，详见 `fpga/sim/dma_timeout_repro/CAM5_IDLE_RECOVERY.md`。
- C5/C6 并非每个统计窗口均达到 30 fps；late-latch 的帧龄收益可能伴随部分相机更新率下降。软件 DMA→GL 返回时间不包含曝光、GPU 异步完成和面板扫描，不能当作完整摄像头到屏幕延迟。
- 本版本板端真实推理验证使用 **RK3568 RKNN NPU**。相关 FPGA 主工程已移除旧自研 NPU，不应据此声称 FPGA 自研 NPU 验收通过。
- 零拷贝、显示卸载和迁移目录包含实验候选与回退快照，请先阅读各自 REPORT/ACCEPTANCE；不把候选数据直接推广为完整六路应用性能。
- 不上传超过 **100,000,000 字节**的文件；大型数据库、工具链、仿真缓存、明文凭据文件及无关内容排除，原始本地文件保留。
