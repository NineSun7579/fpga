# main OV5640 128-bit 图像字打包合同

更新日期：2026-09-02

## 范围

`rgb565_word_packer` 只把已经处理完成的 RGB565 像素流组织为 128-bit
数据字，供后续 DDR3 帧缓存或 PCIe 数据搬运层使用。该模块不负责 OV5640
配置、时钟域交叉、DDR3 事务、PCIe TLP、主机地址或帧尺寸配置。

## 数据布局

- 输入像素按接收顺序编号，像素 0 放在 `word_data[15:0]`，像素 1 放在
  `word_data[31:16]`，依次递增到像素 7 的 `word_data[127:112]`。
- 每个 RGB565 像素占两个连续 byte lane；第一个像素使用
  `word_keep[1:0]`，第二个像素使用 `word_keep[3:2]`，以此类推。
- 完整 8 像素字的 `word_keep` 为 `16'hffff`。不足 8 像素的行尾字只使低
  `2 * pixel_count` 个 byte lane 有效，其余 `word_data` 位必须为 0。
- 该布局只定义本模块的内部数据字语义，不等同于厂商 PCIe AXIS 的
  `tkeep[3:0]` 或主机内存字节序；后续适配层必须另行冻结转换规则。

## 时序与事件

- 输入和输出均同步于同一个 `clk`，不提供输入背压；每个时钟最多接受一个
  `in_valid` 像素。
- 累积 8 个像素后产生一个完整 `word_valid`。打包器允许在输出前保留一个
  待发送字，因此输入可以连续每拍有效。
- `word_frame_start` 和 `word_line_start` 随包含对应首像素的输出字产生。
- `in_line_end` 到达时，若当前字有未满像素，立即输出补零行尾字；若最近
  一个完整字尚在待发送状态，行尾事件附着到该完整字；若该行没有像素，
  输出一个 `word_valid=0` 的控制事件。
- `in_frame_end` 是帧边界控制事件；没有待发送数据时允许以
  `word_valid=0`、`word_keep=0` 的控制事件输出。
- `word_protocol_error` 传播输入协议错误；没有数据字可附着时也允许作为
  控制事件输出。

## 复位与错误边界

- `rst_n` 异步断言；释放时序由集成层负责。
- 复位清空累积字、待发送字和所有输出事件。
- 输入行尾或帧尾不得导致未完成像素被静默拼接到下一行或下一帧；未完成字
  必须补零并以 `word_keep` 标出有效范围。
- 本合同不定义地址单位、帧长度、DDR3 burst、PCIe 最大 payload 或主机
  通知协议。
