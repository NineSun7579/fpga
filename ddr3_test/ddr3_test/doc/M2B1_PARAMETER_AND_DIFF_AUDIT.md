# M2-B1：PG2L100H DDR3 参数与差异审计

状态：当前平台审计；旧 PG2L50H 派生参数和迁移结论已作废。审计日期：2026-09-04。

## 1. 当前目标

```text
RK3568_MES2L100H（FPGA + ARM）
PG2L100H-6IFBG484
Logos2 / PG2L100H / FBG484 / -6
```

活动 DDR3 IP 的目标 header 已是 PG2L100H，但其生成版本、隐藏派生参数、wrapper、FDC/RCF 和板级参数仍需按当前平台重新核验。不能以旧 50H seed、旧 staging 或旧位流替代当前证据。

## 2. 核验范围

使用 PDS 2022.2-SP6.4 对活动 `ddr3.idf` 做只读核验；如发现版本或参数不一致，在 `build/ipgen/pg2l100h` 建立新实例。禁止手改 IDF XML、隐藏参数或厂商生成 RTL，禁止原地覆盖 `ip_core/ddr3`。

必须记录：

- IDF header、生成器版本和完整参数集合；
- `DEVICE_100H_EN` 等与 PG2L100H 相关的派生值；
- controller/PHY wrapper 端口、用户口宽度和握手语义；
- DDR3 颗粒组织、地址位宽、目标速率和参考时钟；
- FDC/RCF 的管脚、电气属性、时钟对象和实际命中情况；
- 仿真模型、filelist、层级和生成日志。

## 3. 当前已知差异

- 活动 IDF 为 PG2L100H，但来自旧 PDS 批次，不能直接证明与 SP6.4 生成结果等价。
- 手写顶层/FDC 与活动 IP 的 `mem_a` 位宽存在差异，必须由实际 DDR3 料号和原理图决定。
- 外层示例包含历史器件位置和旧流程痕迹，不能直接升格为当前约束。
- 旧 50H 参数对照只可说明历史迁移实验的差异，不得作为当前派生参数依据。

## 4. 当前 PG2L100H staging 验收

1. 目标必须为 `Logos2 / PG2L100H / FBG484 / -6`。
2. 生成器必须为 PDS 2022.2-SP6.4，并记录完整版本信息。
3. 参数必须与已审核的颗粒、容量、地址、速率、时钟和用户口合同一致。
4. wrapper/FDC/RCF/仿真资产必须进行目录级差异审计。
5. canonical `ip_core/ddr3` 的内容和 SHA-256 在 staging 操作期间保持不变。
6. 生成后从空 `build/` 重跑 CI-6 和必要的功能/时序仿真。

## 5. 升格门槛

板级资料、IP 参数、端口契约、约束和构建产物均通过审核后，才允许原子升格到 canonical。否则保持 D3-A 阻断，不修改当前 RTL/FDC，不把历史 50H 资产解释为 PG2L100H 通过证据。
