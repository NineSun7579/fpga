# C3/C4 320×240、200%显示、六路同时展示上板验证报告

日期：2026-10-10。版本：`detview_cam34_six`。

> 🧠 **From Hindsight memory (Cam3 cam4 shared 640x480 YOLO recognition)** — 本任务在 RK3568 端合成 C3/C4 供一个共享 YOLO 区域使用；本次需求把显示约束明确为六路 3×2 同时显示，C3/C4 使用低像素密度的缩放纹理。

## 行为

六路仍然同时显示在 3×2 网格。C1/C2/C5/C6 继续使用 640×480 RGB565。C3/C4 从每个 2×2 源像素块计算 RGB 均值，得到实际 320×240 RGB565 缓冲；在原来的 640×480 窗格内由 GPU 放大 2 倍显示，因此窗口宽高不变、显示比例仍为 4:3，只降低细节密度。截图标签显示 C3/C4 `320×240`，其余四路 `640×480`。

推理输入为 C3/C4 两路 320×240 左右拼合后的 640×240 内容，上下各增加 120 行灰色 114，形成模型需要的 640×480。实际 RKNN 查询到 `MVP_accuracy_round1_rk3568_int8.rknn` 输入 `[1,480,640,3]`。内部 canonical 仍保留既有 80 行处理；检测坐标去掉 120 行内容补边和 80 行 canonical 补边，再按 2 倍映射到 C3/C4 窗格。

C3/C4 的显示缓冲每帧 **153,600 字节**（320×240×2），其他四路每帧 **614,400 字节**（640×480×2）。RK3568 仍先 DMA 读取两张原始 640×480 帧，所以 FPGA/PCIe 原始传输量没有减少。

## 100 秒实测帧率

剔除启动阶段，显示统计有效区间 86.197 秒。

| 路 | 采集新帧 | 实际显示上传 | 显示每帧上传量 |
|---|---:|---:|---:|
| C1 | 42.00 fps | 23.61 fps | 614400 B |
| C2 | 42.20 fps | 23.61 fps | 614400 B |
| C3 | 26.04 fps | 22.04 fps | 153600 B |
| C4 | 26.08 fps | 21.72 fps | 153600 B |

C3/C4 两路都更新的共享识别输入约 **23.50 fps**。GUI 收到完整 YOLO 结果 **1144 个 / 84.263 秒 = 13.58 fps**，每个结果同时覆盖 C3 和 C4。5 秒窗口统计的 NPU 完成平均为 **13.71 fps**，单次推理平均 **52.61 ms**。NPU 失败 0，六路采集错误计数均为 0。
