# 六路同时显示，C3/C4 降到 320×240

本版默认保留六路 3×2 布局。C1/C2/C5/C6 仍上传 640×480 RGB565 纹理；C3/C4 对每个 2×2 像素块取 RGB 均值，上传实际 320×240 RGB565 纹理。GPU 在原窗口范围绘制全纹理，因此相对原逻辑 640×480 窗口为宽高各 200% 放大，窗口大小和 4:3 比例保持一致，只有像素密度降低。主窗口自身缩放对六个窗口统一生效。

推理继续共用一个输入：C3/C4 各 320×240，左右合成 640×240，上下各填 120 行灰值 114，成为 640×480 RGB888。内部仍兼容既有 canonical 640×640 契约，模型前去掉 80 行 canonical 补边；映射框时去掉合计 200 行偏移并把 x、y 都乘 2，然后定位到 C3/C4 各自窗口。跨缝框按中心归属，并裁剪在该窗口内。

六个 RAW 采集线程持续运行，3/4 的合成检查仍要求两路新序号、同 source generation、DMA 返回年龄 ≤100ms、偏差 ≤40ms。其他四路不再因 C3/C4 共用推理暂停采集。

压缩当前发生在 RK3568 RAW DMA 后；本次不修改 FPGA/PCIe 协议，也不声称 PCIe 流量减半或减为四分之一。显示上传的 C3/C4 每帧 153600 字节，其他四路每帧 614400 字节。

目标 detview_cam34_six。自检参数 --cam34-six-selftest、--cam34-selftest、--trafficlight-selftest。F 开关共享压缩识别，但六路布局保持；Q 正常退出。板端程序和验证报告由父会话部署、实测。
