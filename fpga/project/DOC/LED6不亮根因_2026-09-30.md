# LED6 不亮根因与修复 (2026-09-30)

## 症状
- LED4(A3) 亮 = 100H PLL1 修复生效，SFP TX 有光
- LED6(A5) 灭 = 50K RX PCS LSM 不同步

## 根因
100H 发送的 idle 有序集 `txd=32'hBC0028BC, txk=4'b1001` 不符合 GE_MODE LSM 的同步要求：

- **字节顺序**：i_txd_2[7:0] = byte0 先发，byte3 最后
- **实际码流**：byte0=K28.5(0xBC), byte1=D8.1(0x28), byte2=D0.0(0x00), byte3=K28.5(0xBC)
- **comma 位置**：K28.5 出现在 byte0(偶) 和 byte3(奇)
- **GE LSM 要求**：comma 必须对齐到偶数字节位置，标准 /I2/ 有序集 = K28.5 + D16.2 交替

50K RX 配置 `CH2_RXPCS_ALIGN=GE_MODE, PCS_CH2_BYPASS_WORD_ALIGN=FALSE`，LSM 检测到 byte3 的 comma 后判定为无效对齐，永不进入同步状态 → `o_p_pcs_lsm_synced_2=0` → LED6 灭。

50K 自身的环回测试能通是因为设置了 `i_force_rxfsm_lsm_2=1`，强制跳过 PCS LSM 等待，直接进入字对齐状态。

## 修复（100H 侧）
将 idle 改为标准 GE /I2/ 有序集（K28.5 + D16.2 重复两次）：

```verilog
// sfp_rx_link.v line 78-81 (已备份 .bak_geidle)
wire [31:0] txd_2 = 32'h50BC50BC;  // byte0=K28.5, byte1=D16.2, byte2=K28.5, byte3=D16.2
wire [3:0]  txk_2 = 4'b0101;       // K 标记在 byte0/byte2 (偶数位置)
```

预期结果：50K PCS LSM 正常同步 → LED6 亮。

## 待修复（反向链路）
50K→100H 视频流使用相同的控制字结构（sfp_video_tx.v）：
- idle_word = `{8'hBC, 1'b0, last_hs, last_vs, 5'b0, 8'h28, 8'hBC}`, txk=4'b1001
- ctrl_word = `{8'hBC, 1'b0, head_hs, head_vs, 5'b0, 8'h28, 8'hBC}`, txk=4'b1001

100H RX 端配置 `CH2_RXPCS_CTC=GE`（启用时钟容差补偿），同样依赖 `pcs_synced_2` 作为 `o_rx_en` 使能条件（sfp_rx_link.v line 157）。若 100H LSM 不同步，cam5/cam6 将无画面。

**方案选择**：
1. **GE 协议对齐**（推荐）：修改 50K sfp_video_tx.v 控制字，使 K28.5 对齐到偶数字节，配合 100H CTC 做标准 GE 传输
2. **绕过 LSM**（快速验证）：100H 也设置 force_rxfsm_lsm_2=1，但需重新生成 hsst_sfp IP（约 30 分钟）

优先验证方案 1，若 CTC 与视频协议冲突再考虑方案 2。
