# FPGA 问题审核结论 + RK3568 新比特流点亮指南

日期: 2026-09-10 ｜ 背景: RK3568 侧上电验证发现 BAR 读全 FF、`pcie_dma_memcpy` 报错、AER UnsupReq+，
并定位到旧测试工程 (`fpga/rtl/camera_ddr3_test_top.v` 等) 的三处缺陷。

## 1. 审核结论 (针对 RK3568 侧的三处缺陷指控)

**三处缺陷均不在本工程 (`ov56401`) 的源码中。** 它们属于另一份旧的独立测试工程
（`fpga/rtl/` 目录结构、单文件 test top、无 crossbar），即**板上现有旧比特流的真正来源**。
本工程对应链路逐条核对结果：

| 旧工程缺陷 | 本工程对应模块 | 核对结论 |
|---|---|---|
| ① 写帧期间冻结桥 FIFO，同一 256bit 字重复写满一帧 | `ov5640_ddr_w.v` | **无此缺陷**。`rd_en = axi_data_valid & axi_data_ready`（:206），逐握手弹出；写状态机 `ov5640_ddr_w_ctrl.v` 每帧发一条 cmd，`axi_dma_write.v` 按 4KB 边界切突发，len 递减到 0 结束，不存在"不弹数据继续写"路径 |
| ② FRAME_WORDS=153600 按 256bit 字计数，帧长错 8 倍 | `ov5640_ddr_w_ctrl.v` + `ov5640_top.v` | **无此缺陷**。帧长以 16 字节为单位：`CAM_DATA_LEN = 1280*720*2/16 = 115200`，`axi_cmd_len = cam_data_len<<4 = 1843200 B` 恰为一帧；`axi_cnt == data_len-1` 置 last，计数准确 |
| ③ BAR0 读窗口背后无帧缓冲 | 设计架构 | **本设计 BAR0 窗口本来就不是帧数据入口**。帧数据在 DDR，主机经 DMA 推送 (BAR1 描述符) 获取；BAR0 用户寄存器 (cam 控制) 经 DMA 引擎按 AXI 地址访问 (见 §3)。旧比特流"BAR0 背后无数据源"的观察，正是旧测试工程架构所致 |

**板上比特流过期**是全部症状的根因：主机枚举到的 BAR 配置 (8K/4K/4K) 与本工程
`ipcore/pcie_test/pcie_test.idf` 完全一致，说明旧比特流出自本工程早期版本（当时 top 还
是原版 pcie_test 示例，DMA 数据源=BAR2 RAM、无相机链路、入站读行为异常→UnsupReq+/全FF）。

**处置**：无需修改任何 RTL；用当前源码重出比特流（本机 PDS 2022.2-SP6.4 已完成，
产物见 §5），RK3568 按 §3 流程点亮。

## 2. 新比特流里主机可见的资源

PCIe: EP `0755:0755`, Gen2 x2, MSI 已使能 (向量 4 位: bit1/0=相机帧完成缓冲 2/1, bit2=NPU)。
BAR0 8KB (数据 RAM 窗口，非寄存器！) / BAR1 4KB (DMA 描述符寄存器) / BAR2 4KB (数据 RAM 窗口)。

### 2.1 BAR1 = DMA 描述符寄存器 ( ips2l_pcie_dma_controller )

| 偏移 | 名称 | 语义 |
|---|---|---|
| +0x100 | CMD | [9:0] 每次 TLP 的 DW 数; [16]=1 用 64 位主机地址; [24]=0 FPGA 读主机(MRd,主机→FPGA) / =1 FPGA 写主机(MWr,FPGA→主机) |
| +0x110 | 主机地址低 32 位 | 写此寄存器触发传输 (o_tx_restart) |
| +0x120 | 主机地址高 32 位 | [16]=1 时有效 |
| +0x1E0 | FPGA 侧 AXI 地址 | **注意是 AXI 总线地址**（不是 BAR 偏移） |
| +0x200 | 总字节数 | 自动按 16B 对齐分拍，尾拍带 wstrb |

推荐编程顺序: `0x100 → 0x120(如用64位) → 0x1E0 → 0x200 → 0x110`（0x110 写入触发）。

### 2.2 FPGA 侧 AXI 地址窗 (crossbar 7x3 按地址路由)

| 地址窗 | 目标 | 说明 |
|---|---|---|
| 0x0000_0000 ~ 0x1FFF_FFFF | DDR3 (M00) | 帧缓冲/NPU 权重/注入区都在这里 |
| 0x2000_0000 + 0x00 | XDMA_ACK | 写 bit[1:0] = 对两块缓冲的帧完成应答（自清） |
| 0x2000_0000 + 0x40 | CAM_EN | 写 bit0 启动相机写 DDR |
| 0x2000_0000 + 0x80 | CAM_ADDR_1 | 帧缓冲 A 基址 |
| 0x2000_0000 + 0xC0 | CAM_ADDR_2 | 帧缓冲 B 基址 |
| 0x2000_0000 + 0x100~0x17C | PREP_*/INJ_* 寄存器组 | **09-11 比特流新增**(寄存器级): PREP_CTRL(+0x100)/THR(+0x104)/SIZE(+0x108)/LANE(+0x10C)/INJ_*(+0x110~0x120)/状态/按键/LED/打点, 读写回读位精确; 阈值的图像功能待像素通路集成 |
| 0x4000_0000 ~ 0x5FFF_FFFF | NPU 寄存器 (M02) | 指令队列/层数 |

cam 寄存器经 DMA 访问的方法：因为 0x1E0 接受任意 AXI 地址，把 0x1E0 指到
0x2000_00xx 即可读写 cam 寄存器。寄存器都是 16 字节对齐的，DMA 数据按
**32 位值放进 16 字节传输的 byte0~3 (小端)** 写入；读回时取同样位置。

## 3. 点亮流程 (RK3568 侧)

```
0) 枚举确认: 0755:0755, Gen2 x2, BAR 8K/4K/4K
   （BAR0/BAR2 MMIO 直读返回内部 RAM 内容，不再是全 FF —— 以此确认新比特流已生效）
   注意: BAR1 描述符寄存器只写不可读（入站只有 bar1 写译码），不要用读回校验描述符
1) 链路自检(可选, DDR 回环): 用"主机→FPGA"写 16B 已知样式到 0x0B000000,
   再用"FPGA→主机"把 0x0B000000 推回 16B 到主机缓冲并比对 —— 双向 DMA + DDR 全通
2) 配置帧缓冲 (两笔"主机→FPGA" DMA, 各 16B):
   0x1E0=0x2000_0080, 0x200=16, 主机src=&0x0A000000, CMD=[24]=0 → 写 CAM_ADDR_1
   0x1E0=0x2000_00C0, 0x200=16, 主机src=&0x0A1C2000, CMD=[24]=0 → 写 CAM_ADDR_2
   (帧大小 = 1280*720*2 = 0x1C2000 B; 两缓冲不要重叠)
3) 启动相机: 0x1E0=0x2000_0040, 0x200=16, src=&1, CMD=[24]=0 → CAM_EN=1
4) 等帧: 收 MSI(bit0/1) 或轮询; 也可先只测链路(跳过 2~4, 直接步骤 5)
5) 取帧 (FPGA→主机推送): 0x1E0=0x0A000000(帧A), 0x200=0x1C2000,
   0x110/0x120=主机DMA缓冲, CMD=[24]=1,[16]=1,[9:0]=32~256 → LPDDR4 缓冲得到整帧 RGB565
6) 回应答: 0x1E0=0x2000_0000, 0x200=16, src=&ack, CMD=[24]=0 → 写 XDMA_ACK
7) 验证画面: 对着镜头遮挡/曝光, 重复 5, 观察帧内容变化; 数据错位/重复 = 抓 PAP_MARK_DEBUG 信号
```

链路排障分界（新比特流下）：
- BAR0 MMIO 直读 → 返回内部 RAM 内容（上电为 0 或随机，**不再是全 FF**）——
  以此区分新旧比特流；
- DDR 回环自检 (步骤 1) 通过 → BAR1 描述符 + 双向 DMA + DDR 通路 OK；
- 步骤 2 后用步骤 5 从 0x2000_0080 推 16B 回主机，能读到 0x0A000000 →
  "主机↔FPGA 双向 + cam 寄存器窗"全通；
- 帧推送失败而寄存器通路 OK → 检查相机是否出帧 (MSI 是否来)。

## 4. 残留风险（与本次缺陷无关，但上板前知悉）

1. 帧完成与缓冲的对应关系 (MSI bit0/1 与 ping-pong 的映射) 建议按 §3 步骤 5 实测标定一次。
2. `DOC/OV5640帧传输完整链路.md` §7 所述"主机直接 Memory Read DDR 帧地址"（路径 A）
   在本 IP 配置下入站读被服务到内部 RAM 窗口，**不代表能透传到 DDR**；请以路径 B (DMA 推送)
   为准。
3. 相机未接/未出帧时 DDR 帧区内容不确定；链路验证先用步骤 5 对已知写入区回读。
