# SFP 光口通信问题分析：100H ↔ 50K 配置对比

## 问题描述
- **50K 板回环测试**：正常 ✓
- **100H ↔ 50K 板间通信**：失败 ✗

### 2.2 PLL 配置 **【关键差异】**

#### 50K (hsst_test)
```verilog
// 单 PLL 配置
PLL_NUM = 1
PLL0_EN = "TRUE"
PLL0_REF_FRQ = 125.0 MHz     // ⚠️ 125MHz 参考时钟
CH2_TX_PLL_SEL = "PLL0"
CH2_RX_PLL_SEL = "PLL0"      // RX 也用 PLL0
```

#### 100H (hsst_sfp)
```verilog
// PLL 配置
PLL_NUM = 1
PLL0_EN = "TRUE"
PLL1_EN = "FALSE"            // ⚠️ PLL1 未启用
PLL0_REF_FRQ = 100.0 MHz     // ⚠️ 100MHz 参考时钟
CH2_TX_PLL_SEL = "PLL0"
CH2_RX_PLL_SEL = "PLL0"

// sfp_rx_link.v 注释说明:
// "PLL1@100MHz Diff_REFCK0 -- PLL0 已让给 PCIe x2"
// 但实际 hsst_sfp.v 中 PLL1_EN = "FALSE"
```

**问题点 1：参考时钟频率不匹配**
- 50K: 125 MHz 参考时钟 (sfp_refckp/n)
- 100H: 100 MHz 参考时钟 (与 PCIe 共用 F6/E6)

| 参数 | 50K TX (CH2) | 100H RX (CH2) | 状态 |
|------|-------------|--------------|------|
| RXPCS_ALIGN | - | GE_MODE | - |
| RXPCS_COMMA_SEL | - | K28.5 | - |
| RXPCS_BONDING | - | Bypassed | - |
| RXPCS_CTC | - | GE (千兆以太网模式) | ⚠️ 关键 |
| COMMA_REG0 | - | 10'b0101111100 (K28.5) | - |

### 2.4 TX 码流协议

#### 50K TX (sfp_video_tx.v)
```verilog
// 数据字 (txk=4'b0000): {pix1[15:0], pix0[15:0]}
// 控制字 (txk=4'b1001): {8'hBC, {1'b0,hs,vs,5'b0}, 8'h28, 8'hBC}
//   byte0 = K28.5 (逗号)
//   byte1 = D28.2 (0x28, GE skip 有序集)
//   byte2 = 状态 {1'b0, hs, vs, 5'b0}
//   byte3 = K28.5
```

#### 100H RX (sfp_rx_link.v) **【关键修复点】**
```verilog
// TX 侧发送 GE 8 拍序列 (为适配 50K RX CTC):
//   拍0..5: idle = {D5.6, K28.5, D5.6, K28.5} = 32'hC5BC_C5BC, txk=0101
//   拍6: skip = {D28.2, K28.5, D28.2, K28.5} = 32'h28BC_28BC, txk=0101
//   拍7: payload (本设计发 idle)

// ⚠️ 问题: 100H 是接收端，这里配置的是 100H->50K 的 TX
// 但 50K->100H 方向需要 100H RX 侧正确配置 CTC
```

## 3. 关键问题点汇总

### 问题 1：参考时钟频率不匹配 ⚠️⚠️⚠️
- **50K**: 125 MHz 参考时钟
- **100H**: 100 MHz 参考时钟（与 PCIe 共用）
- **影响**: PLL 生成的线速率可能存在偏差，导致 CDR 无法锁定

### 问题 2：100H PLL 配置混乱 ⚠️⚠️
- 代码注释说 "PLL1@100MHz" 作为 CH2 时钟源
- 但 `hsst_sfp.v` 中 `PLL1_EN = "FALSE"`
- `sfp_rx_link.v` 中有 PLL1 相关端口但未真正使用
- **建议**: 检查 IP 配置是否正确

### 问题 3：CTC (Clock Tolerance Compensation) 配置 ⚠️
- 100H RX 使用 `RXPCS_CTC = "GE"` (千兆以太网 skip 模式)
- 需要 TX 端按 8 拍循环发送 skip 有序集
- 50K TX 侧 `sfp_video_tx.v` **未发送 GE skip 有序集**
- 50K 仅在控制字中使用 K28.5 + D28.2，但**不是标准 GE 8 拍序列**

### 问题 4：TX/RX 方向混淆 ⚠️
- 100H `sfp_rx_link.v` 中配置了 TX 8 拍序列（这是 100H->50K 方向）
- 但问题是 **50K->100H** 方向，需要 50K TX 侧发送正确的 skip 序列

## 4. 修复建议

### 方案 A：统一参考时钟频率 (推荐)

#### 选项 A1：100H 改用 125 MHz 参考时钟
1. 在 100H 板上找一个 125 MHz 时钟源（如果有）
2. 重新配置 `hsst_sfp` IP：`PLL0_REF_FRQ = 125.0`
3. 修改约束文件 `sfp.fdc`

#### 选项 A2：50K 改用 100 MHz 参考时钟
1. 在 50K 板上找一个 100 MHz 时钟源
2. 重新配置 `hsst_test` IP：`PLL0_REF_FRQ = 100.0`
3. 修改约束文件

### 方案 B：修复 50K TX 侧 CTC 序列 (必须)

修改 50K 的 `sfp_video_tx.v`，使其符合 GE CTC 规范：

```verilog
// 在 fab_clk (125MHz) 域增加 8 拍计数器
reg [2:0] tx_phase;
always @(posedge fab_clk or negedge fab_rst_n) begin
    if (!fab_rst_n)
        tx_phase <= 3'd0;
    else
        tx_phase <= tx_phase + 3'd1;  // 0..7 循环
end

// 拍6 发送 skip 有序集，其他拍发 idle 或 payload
localparam [31:0] SKIP_WORD = 32'h28BC_28BC;  // K28.5/D28.2
localparam [3:0]  SKIP_K    = 4'b0101;

// 原有打包逻辑在拍7执行，拍6强制插入 skip
always @(posedge fab_clk) begin
    if (tx_phase == 3'd6) begin
        txd <= SKIP_WORD;
        txk <= SKIP_K;
    end
    else begin
        // 原有的数据字/控制字打包逻辑
        ...
    end
end
```

### 方案 C：100H RX 侧禁用 CTC (备选)

如果无法修改 50K TX：

```verilog
// 修改 hsst_sfp IP 配置
CH2_RXPCS_CTC = "Bypassed"  // 从 "GE" 改为 "Bypassed"
```

**风险**: 时钟容差补偿被禁用，可能导致长时间运行后累积误差。

### 方案 D：检查并修复 100H PLL 配置

```verilog
// 如果 CH2 确实应该用 PLL1:
PLL1_EN = "TRUE"             // 从 "FALSE" 改为 "TRUE"
PLL1_REF_FRQ = 100.0         // 或 125.0，取决于硬件
CH2_TX_PLL_SEL = "PLL1"      // 从 "PLL0" 改为 "PLL1"
CH2_RX_PLL_SEL = "PLL1"
```

## 5. 诊断步骤

### 5.1 检查 100H RX 链路状态
在 100H 代码中检查以下信号（已有寄存器 +0x144）:
```verilog
sfp_st_pll_lock      // bit[0] PLL 锁定
sfp_st_txlane_done   // bit[1] TX lane done
sfp_st_rxlane_done   // bit[2] RX lane done ⚠️ 关键
sfp_st_pcs_synced    // bit[3] PCS LSM 同步 ⚠️ 关键
```

**预期故障点**:
- `sfp_st_rxlane_done = 0` → CDR 未对齐（参考时钟问题）
- `sfp_st_pcs_synced = 0` → PCS 未同步（CTC/comma 问题）

### 5.2 ILA 抓取关键信号（如有 ChipScope/DebugCore）
```verilog
o_rxd_2       // 接收到的原始数据
o_rxk_2       // K 码指示
o_p_lx_cdr_align_2    // CDR 对齐
o_p_pcs_lsm_synced_2  // PCS 同步
```

### 5.3 50K TX 侧验证
回环测试正常说明 50K TX/RX 内部一致，但不代表符合 GE 标准。
用逻辑分析仪抓取 50K TX 输出，确认是否有周期性 skip 有序集。

## 6. 推荐修复顺序

1. **立即**: 检查 100H `hsst_sfp` IP 配置文件 (`hsst_sfp.idf`)，确认 PLL 配置
2. **高优先级**: 统一参考时钟频率（方案 A）
3. **高优先级**: 修复 50K TX 侧 CTC skip 序列（方案 B）
4. **验证**: 读取 100H 寄存器 +0x144，检查链路状态
5. **备选**: 如果硬件无法更改，考虑禁用 100H RX 的 CTC（方案 C）
