# 决策与计划：主机驱动以选项 1 为准 + FPGA 侧补齐 PREP 寄存器载体

## 决策结论

**主机侧按选项 1 实现**（BAR1 参考 DMA 协议 0x100/0x110/0x120/0x1E0/0x200 + CH0~CH4 通道抽象，PREP_*/INJ_* 标"待集成"），理由（全部经 RTL 核实）：
- `prep_regs` 及整个 `preprocess/` 目录（9 个文件）在 top.v 中 0 次例化，任何已出比特流都不含 PREP/INJ 寄存器 → 选项 2 眼下无可验证载体；
- 当前已验证比特流（bitstream_2026-09-10）真实含 BAR1 描述符协议 + ov5640_reg（0x2000_0000 窗口经 DMA 访问）→ 选项 1 当下可端到端打通；
- 选项 3 可行但放弃通道抽象，PREP 上线后需返工。

**FPGA 侧（本仓库）同步做两件事**：把契约落成 v1.1 文档（唯一同源依据），并把 prep_regs **寄存器段**集成进 top.v 重出比特流——使选项 2 的验证前提尽快成立（像素通路接入为第二阶段，不在本计划）。

## 执行步骤

### 第 1 步：Route-0008 根因修复复验（阻塞项，先做）
- 昨晚重编译不可布线的根因已定位：重建 scale_mul_unsign_s3.v 时误从双胞胎模块复制了 `(* syn_multstyle = "logic" *)` 属性，强制 cat_add 的十余个 32×25 乘法器走 LUT → +1472 寄存器、布线失败（日志证据：`Convert attribute name from syn_multstyle` + `mul_low_r` Public-4008 警告）。属性已删除，**综合复验被中断未跑**。
- 执行：`pds_shell -run synthesize`（project_build 副本，~6 分钟），校验 `Total Registers` 回到 ~53006 基线（预期 +300 内来自正常噪声）；若仍 +1000 以上，则升级排查（二分 15 个 conv11/out_buf 文件的 hoist）。

### 第 2 步：ModelSim 侧 prep_regs 集成件开发
- 新增 `sim/preprocess/tb_ovreg_axil_decode.v`：译码器 + ov5640_reg + prep_regs 三件套背靠背 TB——写读 0x...040（CAM_EN 段）、0x...104（PREP_CTRL 段）、边界地址（未命中段），验证地址分发与 b/r 回路由。
- 新增 `source/ov5640/ovreg_axil_decode.v`（~80 行）：输入 ovreg_axil_*（32 位 AXI-Lite），按 `addr[8]` 分发两路 AXI-Lite master（0→ov5640_reg 段 0x00~0xFF，1→prep_regs 段 0x100~0x1FF）；AW/AR 握手锁存地址位，B/R 按锁存位路由回主机。
- 跑 `sim/preprocess/run_all.sh` 回归（prep_regs 相对译码不变，现有 TB 不受影响）。

### 第 3 步：top.v 集成 prep_regs（寄存器段，不含像素通路）
- 前置：`tasklist` 确认 pds.exe（GUI）已关闭（需编辑 project/project.pds 注册新文件——陷阱 #3；若 GUI 在跑，请用户关闭后继续）。
- top.v 改动（~15 行）：axi_to_axi_lite 的输出 ovreg_axil_* 改接 ovreg_axil_decode；decode 的两路 master 分别接 ov5640_top 的 s_axi_*（原有连接）与新例化的 prep_regs。
- prep_regs 例化（top.v）：`clk(axi_clk)`、`rst_n(~axi_rst)`；无实际来源的输入按安全默认 tie（inj_busy/inj_done/pipe_*/btn_*/lane_*/ts 脉冲 = 0），输出悬空（inj_start/inj_done_clr/btn_sticky_clr/led_ctrl 不接）——像素通路集成（第二阶段）时再接真信号，本阶段寄存器可读写回读、状态位为 0。
- project.pds 注册 `../source/ov5640/ovreg_axil_decode.v`。

### 第 4 步：全流程重出比特流
- pds_shell `-run gen_bit_stream`（project_build 副本，后台，预期 25~40 分钟——Route-0008 根因修复后路由应恢复正常速度）。
- 产物：`bitstream_2026-09-11/`（top.sbit + top.smsk + 时序摘要 + README）；时序与 09-10 基线对照记录（历史 pclk -0.192ns 情况一并记录）。
- ModelSim 全量回归确认全绿（sim/npu 7/7 + sim/preprocess 10/10）。

### 第 5 步：契约文档 v1.1
- `DOC/FPGA_RK3568_传输协议_v1.md` 升级 v1.1（或新增 v1.1 节）：
  - 寄存器总表加**实现状态列**：已实现（BAR1 描述符 0x100/0x110/0x120/0x1E0/0x200；CAM_ACK/EN/ADDR_1/ADDR_2 @0x2000_0000+0x00/40/80/C0；PREP_*/INJ_* @0x2000_0100~0x017C —— 本比特流新增）；待集成（PREP 阈值的图像功能——需第二阶段像素通路）；
  - 并入点亮指南内容：BAR1 描述符表、CAM/PREP 寄存器经 DMA AXI 地址访问方法（值放 16 字节传输 byte0~3）、DDR 回环自检、7 步点亮流程；
  - 主机侧选项 1 实现清单：传输层（BAR1 描述符 + MSI + ov5640_reg/prep 经 DMA 方法）→ CH0~CH4 抽象 → PREP 后端由 stub 转正式。
- 更新 `DOC/RK3568_新比特流点亮指南.md`（PREP 寄存器回读步骤 + out_col 经验）与 `DOC/NPU图像处理一致性验证报告.md` §6（Route-0008 根因闭环）。

## 验收标准
1. 综合 `Total Registers` ≈ 53006 基线（±prep_regs 预期增量，无 +1000 级跳变）；
2. 全流程布线成功（无 Route-0008），新 sbit 交付；
3. ModelSim：sim/npu 7/7 + sim/preprocess 11/11（新增译码器 TB）全绿；
4. 契约文档 v1.1：每个寄存器有明确"已实现/待集成"状态与访问方法，主机侧可直接照表实现选项 1。

## 风险与边界
- pds.exe GUI 若仍在运行会回写 project.pds 覆盖注册改动 → 第 3 步前置检查；
- 译码器 B/R 路由错误风险 → 专项 TB 覆盖（第 2 步）；
- PREP 阈值写入了也不会改变图像（像素通路未接）→ 文档诚实标注，避免主机误判；
- 若综合复验仍 +1000 寄存器 → 根因升级为 hoist 二分排查（备选方案：回退 15 个 conv11/out_buf 文件的 hoist，ModelSim 改走 sim 专用 filelist）。
