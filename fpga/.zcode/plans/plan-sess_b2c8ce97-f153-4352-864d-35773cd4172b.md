# OV5640 双路修复 — 目标：明早 9 点前交付不撕裂、不卡顿的双路 640×480 画面

## 根因（已逐文件验证）
1. **RTL 双账本（撕裂+卡顿核心）**：帧完成判据 `ov5640_ddr_w.v:216` 的计数器版 `axi_data_last` 被 vsync 脉冲清零（:184-199），而 vsync 到来时尾部 beat 还滞留在两级 FIFO → 完成信号永不触发 → FSM 卡 DATA → 0.16s 看门狗 abort → 零 beat 填尾 + 下帧错位 → 撕裂；每坏帧耗 0.16s → 卡顿。DMA 侧权威账本（`len`）的完成信号 `data_in_last` 在 `top.v:1193/1235` 悬空未接。
2. **camview 仍按 1280×720 读帧**（帧长 0x1C2000），RTL 已是 640×480/0x96000 → 多读 1.2MB 死区=花屏，tag 地址全错。
3. **cam2 复位不使能**（top.v:1023 CAM_EN_DEF=0）且 camview 从不写 CAM2_EN → 半边黑。
4. **camview 盲乒乓**（expected^=1 不校验 FRTAG）→ 丢一帧后 ACK 相位永久错 → FPGA 阻断出帧 → 卡死。

## 执行步骤

**A. RTL 单一账本（6 处小改，无新文件，project.pds 不动）**
- `axi_dma_write.v`：`data_in_last` 改为 `trans` 下降沿脉冲（每命令恰好一次，覆盖正常完成+两个看门狗 abort 路径）。
- `ov5640_ddr_w_ctrl.v`：新增 `dma_done` 输入；DATA 态退出、`w_ping/frame_cnt/s_xdma_req/last_cnt` 全改由 `dma_done` 驱动，看门狗保留兜底。
- `ov5640_ddr.v`/`ov5640_top.v`：加 `dma_done`/`cam_dma_done` 端口透传。
- `top.v`：两处 DMA `.data_in_last()` 接 `cam_dma_done`/`cam2_dma_done`；cam2 `CAM_EN_DEF`→1'b1。
- `ov5640_ddr_w.v` 计数器降级纯 debug（不动逻辑）。

**B. 主机 `host/camview/main.cpp`**
- IMG_W/H→640/480（帧长 0x96000，tag 地址自动派生）；启动 ACK=3 两路 + 显式写两路 CAM_EN=1。
- 主循环改 tag 驱动：轮询 4 个 FRTAG → 每路只读 tag 前进的缓冲 → 仅 ACK 该缓冲，无新帧短睡重轮询，废除盲乒乓。
