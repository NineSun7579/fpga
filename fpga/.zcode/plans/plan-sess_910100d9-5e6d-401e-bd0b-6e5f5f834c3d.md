# 计划：撕裂根治（RTL 帧序号）+ detview 检测画框部署（.rknn → RK3568 NPU）

**已定结论**：传输链路保持 RGB565（传感器 8bit DVP 只有 565，传输 888 无信息增益、白多 50% 带宽）；喂模型时主机侧转 RGB888（位复制），这才是"改用 RGB888"的正确落点。不动 NPU 相关任何东西。

---

## 第一部分：撕裂根治 — RTL 帧序号写入 DDR 帧尾

### 设计（纯增量式，不碰主通路）

- **`source/ov5640/ov5640_ddr/ov5640_ddr_w_ctrl.v`**（帧尾写序号）：
  - 现状 FSM：IDLE →(vsync)→ ADDR(发一笔命令 addr=帧基址 len=614400B) → DATA(流到 last) → IDLE。
  - 改动：DATA 的 last 拍后**追加一笔 16B 写**：地址 = 当前帧基址 + `CAM_DATA_LEN×16`(=0x96000)，数据 = 32bit 帧计数器（byte0~3，小端），计数器每帧 +1，复位为 0。
  - 实现为新增 2 个状态（ADDR_TAG/DATA_TAG）+ 计数器寄存器；若 tag 命令握手异常**立即回 IDLE**，绝不阻塞主帧流（保证最坏情况只是序号缺失，相机永不停止）。
  - 需先核实 `top.v:1069-1109` 的 `axi_dma_write` 是否接受背靠背两条命令（实现时第一步确认；若不支持则在其上游做小适配）。
  - 数据流注入：在 ctrl 内对 `axi_data_*` 做透传 + 帧尾注入 1 拍计数器（ctrl 已看到 valid/ready/last，天然位置）。
  - 注意：该文件含 GBK 中文注释，编辑只用 ASCII 锚点做精确替换。
- **地址布局**（零冲突，纯追加）：A 帧序号 @ `0x00896000`，B 帧序号 @ `0x00A96000`。
- **主机侧取帧规则**（detview 内实现）：只读 DDR（M00 安全通道）两个序号槽，**显示序号更大的缓冲**（正在被写的缓冲序号恒为次大 → 数学上读写永不相撞，撕裂归零），序号无变化则等 5ms 再查。自动兼容旧比特流：序号槽恒 0/不变 → 退回"双读稳定校验"模式。
- **重出比特流**：确认无 pds_shell/pds.exe 进程、PDS GUI 已关 → 清空 `project/{compile,synthesize,device_map,place_route}` → pds_shell 全流程（≈33 分钟，NPU 保留在比特流里不动）→ 产出 top.sbit。
- **烧录与恢复**（给出命令清单，由你执行）：JTAG 烧录 → PERST(GPIO144) → remove/rescan → rmmod/insmod → 验证撕裂消失。

## 第二部分：detview — .rknn 部署 + Qt 检测框

### A. 前置：RKNN 运行时 2.3.2（硬性版本匹配）
- 下载 `librknnrt.so`(aarch64, 7,726,232B) 与 `rknn_api.h`，来源 `github.com/airockchip/rknn-toolkit2` tag `v2.3.2`；Python 提取 `librknnrt version:` 校验。失败则改由你从转换环境提供。

### B. 新建 `host/detview/`（qmake，camview 风格，不改 PCIe 协议）
- `pango_dev.{h,cpp}`：照搬 camview 的 ioctl(MAP/H2F/F2H)+mmap+SIGALRM 看门狗（已验证代码）。
- `frame_source.{h,cpp}`：读帧 + 序号新鲜度判断（见上）+ ACK 写（保留，兼容流控）。
- `rgb565.{h,cpp}`：565→888 位复制（r8=(r5<<3)|(r5>>2) 等），受 B/C 热键的字节序/红蓝设置影响（与显示一致）。
- `letterbox.{h,cpp}`：640×480 → 640×640，上下各补 80 行，记录 pad；逆映射 `y_src = y640 − 80`。
- `yolo26_rknn.{h,cpp}`：`rknn_init/run/outputs_get(want_float=1)`；
  - **e2e** `[1,300,6]`（x1,y1,x2,y2,score,class_id，已排序无 NMS）：score≥0.25 过滤 → 反 letterbox → clamp；
  - **std** `[1,4+nc,8400]`：解 cx,cy,w,h + 各类分数 → 置信度过滤 → IoU 0.45 NMS（自写，不用 OpenCV）；
  - 输入 RGB uint8 NHWC（模型内部做归一化）。
- `main.cpp`：采集线程 → 帧池（满丢旧）→ 推理线程 → UI；QPainter 画框+类别+score+FPS+推理耗时；热键：**1/2/3/4 切换 4 个模型**（默认 1=zebra_3cls_e2e：0 zebra/1 vehicle/2 person）、B 字节序、C 红蓝、F 全屏、P 暂停、H 帮助。
- `detview.pro`：`QMAKE_RPATHDIR += /root/ov5640/lib`（自带 .so 用 rpath，工程内首个先例）。

### C. 部署包 `usb_deploy/detview/`
- 源码 + `.pro` + `models/*.rknn`(4 个) + `lib/librknnrt.so` + `include/rknn_api.h` + `install_detview.sh`（复制到 `/root/ov5640/{detview,models,lib}` → 板上 `/usr/lib/qt5/bin/qmake && make -j4` → PCIe 驱动重载仪式 → 启动前环境自检：`dmesg | grep -i rknpu`、qmake 存在性）+ `run_detview.sh`（`/tmp/detview.lock` 单实例 + DISPLAY/XAUTHORITY）。
- 大文件走 U 盘（.so+.rknn ≈16MB，不走串口）。

### D. 上板验收
1. 环境自检（rknpu 内核驱动版本；缺失则单独处理，这是唯一外部硬依赖）。
2. 单帧验证：抓一帧 dump → 推理 → 框坐标核对（对镜头摆已知物体）。
3. e2e vs std 实测帧率对比（README 警告 e2e 可能 CPU 回退），取快者做默认；目标 ≥24fps@640，不达标则隔帧推理。
4. 撕裂验证：新比特流下长时间观察无撕裂；旧比特流退回缓解模式。

## 执行顺序
1. detview 全套代码 + 部署包（主机侧，先写完）
2. RTL 帧序号改动（`ov5640_ddr_w_ctrl.v` + 必要的 top.v 适配）
3. pds_shell 重出比特流（~33min，自动跑，产出后给你烧录命令）
4. 你烧板 → detview 上板联调（我给逐步命令，按串口/U盘流程）

## 风险
1. rknpu 内核驱动缺失/过旧 → 需升级，出现时单独决策。
2. e2e 模型 CPU 回退帧率不达标 → std+NMS 后备已内置。
3. RTL 改动回归风险 → 纯增量设计 + 主流永不被阻塞；旧比特流（`bitstream_2026-09-13` 归档）可随时回烧。
4. RGB565 位序/通道序 → B/C 热键现场校正 + 一次色卡验证。
5. prep_regs/M01 读不可信 → 全程不读 M01（序号走 DDR 通道，天然规避）。
