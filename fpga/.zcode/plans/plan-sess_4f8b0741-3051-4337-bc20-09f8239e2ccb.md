# OV5640→RK3568 显示链路修复 + NPU 删除 + Qt5 实时显示应用

## 总体思路

显示链路 = `OV5640(DVP, RGB565 1280×720) → FPGA 写 DDR3 → PCIe DMA → RK3568 → Qt 应用 → HDMI 显示器`。三段工作：
1. **FPGA 侧**：物理删除 NPU 缩短编译 + 补一个帧状态寄存器，重编译出比特流
2. **板上验证**：烧写 + 用现成探测脚本确认帧数据流入 DDR
3. **主机侧**：RK3568 装 Qt5，写 camview 应用实时显示相机图像

## 关键事实（探索已确认）

- `source/HDMI/` 是 HDMI **输入**采集（未编译）；FPGA 板本身无视频输出，显示全靠 RK3568
- NPU 已被 `NO_NPU` 宏屏蔽（top.v:6），物理删除=归档文件+清 project.pds 条目；现配置全流程编译仅 ~6 分钟
- 寄存器表（0x2000_0000 窗）：+0x00 XDMA_ACK（写后单拍脉冲，bit0/1 对应缓冲1/2）、+0x40 CAM_EN、+0x80/0xC0 乒乓地址、+0x30/+0x34 调试计数器（**已在源码但未编译**，昨晚 22:12 打入）
- `xdma_req[1:0]`（帧完成标志）在 ov5640_top.v:227 现成存在，但未暴露给主机 → Qt 应用无法知道哪个缓冲就绪，需补 +0x38 状态寄存器
- 板载 DMA 驱动用法已被脚本矩阵实测：`IOWR(2)` 映射 TX(offset 0)/RX(offset 1MB) 缓冲 → `IOWR(4)` 主机写寄存器/DDR → `IOWR(5)` 主机读。板子经 COM9@1500000 连本机，`sh.py`/`shf.py` 可远程执行
- 帧参数：1280×720×2 = 1,843,200 字节/帧，28.58fps，乒乓地址用实测过的 0x00800000/0x00A00000

## 执行步骤

### Step 0 前置检查
- `tasklist` 确认无 pds 进程（PDS 单实例陷阱）
- 归档：project.pds → .bak、旧比特流 top.sbit → `bitstream_2026-09-12_before_npu_removal/`
- 串口探测板环境（决定 Qt5 安装路径）：OS 版本、`dpkg -l | grep qt5`、qmake/g++ 有无、网络通不通（apt 源）、Xorg/fb0 显示环境、pango 驱动在位

### Step 1 RTL 修改（Python 字节级，GBK 安全，改前备份）
1. **NPU 物理删除** → 归档 `_attic/unreachable_npu/`（保留相对路径）：
   - `source/npu/` 78 个 .v、`source/pcie2npu/` 3 个 .v、`axi_crossbar/npu_to_core_cdc_bridge.v`
   - `axi_dma/axi_dma.v`、`axi_dma_read.v`（⚠️ `axi_dma_write.v`/`stream_pipe.v` 相机在用，保留）
   - `ipcore/{ins_cdc,mul,ov5640_cdc_fifo_D}/`（NPU 专用 IP + 1 个死 IP）
   - project.pds 删 80 个 `_file` 块 + 3 个 `_ip` 块（154→74 条目校验）
   - top.v 保守清理：保留 `define NO_NPU`、S02~S06/M02 tie-off 与 crossbar 端口映射；仅删 `ifndef NO_NPU` 死实例块
2. **新增 +0x38 帧状态寄存器**（Qt 应用同步用，同时钟域 4 处小改）：
   - `ov5640_reg.v`：加 `input [1:0] dbg_xdma_req` 端口 + `REG_DBG_XDMA_REQ = BASE+0x38` + 读 case 分支
   - `ov5640_top.v`：ov5640_reg 例化处 `.dbg_xdma_req(xdma_req)`（信号 227 行现成）
   - 实施时在 ov5640_ddr_w_ctrl.v 确认 bit0/bit1 ↔ addr_1/addr_2 对应关系并写入交付文档
3. 复查：`python _attic/reachability_check.py top`（预期死文件只剩 preprocess 9 个有意下线模块）

### Step 2 FPGA 编译验证（~10 分钟/轮）
- 清空 `project/{compile,synthesize,device_map,place_route}` → pds_shell 标准全流程
- 判据：无 `E:` 错误、`All Constraints Met`、top.sbit 生成；hold 随机违例则重跑

### Step 3 烧板 + 帧通路验证
- JTAG 烧写 → PERST → PCIe rescan（不 rescan 一切 DMA 静默死锁）
- 寄存器回环：CAM_ADDR 写读、CAM_EN 回读
- cam_alive3.py 全流程：设地址 → ACK=3 → CAM_EN=1 → 轮询 DDR 数据变化 + MSI 计数
- dbg 计数器二分定位：+0x34 vsyncs 不涨→DVP 断（查 IODELAY/pwdn）；涨而 words 不涨→capture 断；都涨 DDR 无数据→写引擎；DDR 有数据→转 Step 5
- RTL 有改动则回 Step 2（每轮 ~10 分钟，时间充裕）

### Step 4 RK3568 安装 Qt5（按 Step 0 探测结果分支）
- 有网：`apt-get update && apt-get install -y qtbase5-dev qt5-qmake g++ make`
- 无网但有 Qt 运行库：仅补 -dev 包（离线 deb 经串口 base64 传输，_xfer.py 现成）
- 验证：板上编译一个最小 Qt 窗口跑通（xcb 或 linuxfb 平台插件）

### Step 5 camview Qt 应用（源码放 `host/camview/`，qmake 工程）
- **驱动接入**（复刻已验证的 C 调用序列）：open /dev/pango_pci_driver → MAP TX(4MB)/RX(10MB) → mmap
- **同步协议**：写 addr1/addr2 → ACK=3 → CAM_EN=1 → 循环{ 轮询 +0x38 → 就绪缓冲 N：IOWR(5) 读 1.84MB 帧 → ACK bit N → 显示 }（读后即 ACK，保证不欠帧）
- **显示**：`QImage::Format_RGB16` 直接包装帧数据（零转换）→ 缩放 → QLabel/paintEvent；标题栏显示 fps/vsyncs/cam_words 健康状态
- **热键**：B 字节序切换、C 红蓝交换（上屏颜色校准用）、F 全屏、Q 退出
- **健壮性**：ioctl EINTR 超时看门狗、启动时寄存器回环自检、xdma_req 3 秒无帧时屏上提示
- 板上 qmake && make -j4 编译，DISPLAY=:0（必要时 XAUTHORITY/sudo -u linaro，兜底 linuxfb）
- 验收：HDMI 显示器出现实时相机画面，连续 ≥1 分钟无冻结，帧率接近 28.6fps

### Step 6 交付（9:00 前）
- `project/generate_bitstream/top.sbit`（无 NPU + +0x30/34/38 调试/状态寄存器）+ 时序/资源报告 + reachability 记录
- 板上 Qt5 环境 + camview 可执行 + 源码（host/camview/）
- `DOC/` 交付说明：修改清单、新寄存器(+0x38)与 ACK/bit 对应表、启动命令、已知问题
- 全程可回滚：_attic 归档 + .bak 备份 + 旧比特流

## 风险与对策
- 板无网络且无 Qt dev 包 → 离线 deb 串口传输（慢但可行）；彻底无 Qt 则交付 deb 清单+说明
- 串口 root 会话无 X 权限 → sudo -u linaro / XAUTHORITY / linuxfb 三级兜底
- hold 随机违例 → 重跑 PnR
- 颜色/字节序错 → 热键现场校准后固化
- 每次 pds_shell 前 tasklist 查单实例；改工程文件前确认 PDS GUI 未开
