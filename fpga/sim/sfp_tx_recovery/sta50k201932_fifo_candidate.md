## Reviewable candidate

Preferred storage exception uses the RAM clock-pin startpoints, an RD through collection, and the actual head input endpoints. It excludes only the ownership transfer; fab RAD->RD and local WADM setup/hold remain obligations.

```tcl
set_false_path -from [get_pins -hierarchical {u_sfp_video_tx/u_fifo/mem_*/ram32x1dp/WCLK}] -through [get_pins -hierarchical {u_sfp_video_tx/u_fifo/mem_*/ram32x1dp/RD}] -to [get_pins -hierarchical {u_sfp_video_tx/head_q*/I*}]
set_max_delay 16.000 -datapath_only -from [get_clocks mrg_clk] -to [get_pins -hierarchical {u_sfp_video_tx/u_fifo/wptr_rd1*/D}]
set_max_delay 8.000 -datapath_only -from [get_clocks p_clk2core_tx_2] -to [get_pins -hierarchical {u_sfp_video_tx/u_fifo/rptr_wr1*/D}]
```

This exact candidate is `fifo_narrow_storage.fdc` in the isolated directory. TA accepted all three commands with no diagnostic in `ta_collect_final_stdout.txt`. PDS User Guide printed pages 207–209 explicitly defines clock-pin startpoints and through points. Clock-from for Gray data means all actual register clock origins driven by that clock, restricted to the ten first-stage D destinations; it includes binary-MSB aliases without guessing mapped Q pins. No second-stage or RS endpoint matches these destinations. No clock family is declared asynchronous.

Runtime help supports the alternative primitive-arc syntax:

```tcl
set_disable_timing -from WCLK -to RD [get_cells -hierarchical {u_sfp_video_tx/u_fifo/mem_*/ram32x1dp}]
```

Do not apply both storage forms. The arc form is documented in User Guide printed page 209 but was **not successfully timing-tested**: TA raised Timing-0081 when attempting to install it. The path form above was successfully accepted and avoids dependence on that arc API's model initialization.

PDS `set_max_delay -help` confirms `-datapath_only`; User Guide printed pages 200–201 says it removes clock skew/jitter, includes launch CLK->Q, combinational delay and receiver setup, and suppresses hold analysis only on the selected max-delay paths. Thus these values are conservative bus propagation bounds, not a claim that hold remains analyzed on the Gray CDC crossing. No false path is applied to those Gray D paths, which would supersede max-delay analysis.

A falling-edge **separate write-address register** is a possible structural fallback, not implemented or simulated here. Its contract must be: falling edge captures current binary write address; next rising edge writes that address while pointer/full update retain existing accepted-write semantics. First accepted write after reset must occur only after that falling-edge capture is valid, or address register must have a proven initialized address consistent with wbin. Reset deassertion, full gating, wrap, and arbitrary read/write phase need a FIFO scoreboard. It adds a half-cycle wbin->address setup obligation and falling-to-rising address->RAM setup obligation, which must be analyzed with the actual duty cycle. Changing the shared FIFO would affect merge and TX; use an instance-scoped parameter or distinct wrapper only after a validated contract. No RTL delay chain or clock cut is proposed.
