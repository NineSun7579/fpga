# 六路视频光口传输验收报告(2026-09-29)

## 目标

50K 板(PGL50H)双摄 OV5640 → SFP0 光纤 → 100H 板(PG2L100H)接收拆分为 cam5/cam6,
与本地 4 路 DVP 相机合成,经 PCIe → RK3568 camview **3x2 六宫格**显示。

## 系统架构

```
[50K MES50HP/PGL50H]                                    [100H PG2L100H-6FBG484]
cam1/cam2 OV5640 480p60 ─ cam2_merge 1280x480 ─┬─ HDMI 720p30(保留)
                                               └─ sfp_video_tx → HSST CH2 5G/8B10B/32bit@125M
                                                        │ SFP0
                                                        ▼ 光纤
                                               QR3(HSSTLP_364_918)CH2 RX(PG2L100H)
                                               hsst_sfp IP(PLL1@100M Diff_REFCK0)
                                                        ▼
                                               sfp_video_rx(符号流 FIFO 保序解包)
                                                        ▼
                                               sfp_rx_cam_if(拆列 640+640 + CDC → axi_clk)
                                                        ▼
                          cam5: ov5640_ddr + axi_dma_write ─┐   cam6: 同构 ─┐
                                                            ▼               ▼
                                               ddr_w_arb(6 主轮询, m4/m5 新增)
                                                        ▼
                              DDR3 乒乓: cam5 0x0180/0x01A0_0000, cam6 0x01C0/0x01E0_0000(FRTAG 同 cam1~4)
                                                        ▼ PCIe(x2 Gen2, PLL0)
                                               RK3568 camview 六宫格(1920x960)
```

## 关键设计决策

1. **PLL 分配**:QR3 象限 PLL0 被 PCIe IP 独占(U0/U1 lane),SFP 的 hsst_sfp IP 重配为
   **PLL1**(Diff_REFCK0/100MHz/M=1/N1=5/N2=10/VCO 5000,与 PLL0 同参),CH2_TX/RX_PLL_SEL=PLL1,
   lane 放 U2。参考时钟 F6/E6 与 PCIe 共用同一对 GT 焊盘(同象限内 REFCK0 路由到 PLL1)。
2. **接收端解包保序**(`source/sfp/sfp_video_rx.v`):数据字拆 2 个像素符号、**电平变化的**
   控制字入队、电平不变的控制/idle 字丢弃(否则 125M 全速字流必溢出 1 符号/拍的出队速率)。
   符号流单 FIFO 保证 vs/hs 电平更新不会越过积压像素。
3. **列拆分**(`sfp_rx_cam_if.v`):vs 上升沿清列计数、de 期间计数,x<640→cam5 其余→cam6。
   以帧首对齐,行内 de 断续不错位。CDC 用 19bit 格雷码异步 FIFO(video_async_fifo,50K 同款)。
4. **写链复用**:cam5/cam6 完全复用 ov5640_ddr + axi_dma_write 模式(含 FRTAG 帧标签),
   cmd_id=0011/1100,ddr_w_arb 扩 6 主(选择器 2→3bit,轮询逻辑同构)。
5. **50K 侧两处协议 bug 修复**(仿真发现):
   - fix1:TX pix_pend 配对不滚动(偶数列全部重复首像素,棋盘状错乱);
   - fix2:idle 字丢失 vs/hs 电平(FIFO 行内常态排空,空闲字把 hs 拉 0,行计数错乱)。

## 50K 侧(Rev3.2 精简版,本机 `ov56401\ov5640_sfp480p_test`)

工程由对方电脑转回本机后做 **Rev3.2 精简改造**(用户要求,加速编译):

- **注释整条 DDR3+HDMI 显示链**:fram_buf/sync_vg/DDR3_50H IP/ms72xx_ctl/HDMI 输出端口与
  fdc 全部 DDR/HDMI 约束(build.tcl 同步裁剪 16 个文件)
- **SFP 视频源直连 cam2_merge 输出**:merge o_clk 与 sfp_video_tx vid_clk 同域,不再经 DDR
- **时钟方案**:merge 读侧按 100M 设计,125M 直连有 -0.97ns 域内违例;用 clk2core_tx
  二分频得 mrg_clk 62.5M(读出需求 ~54M,裕量足),该域与原 core_clk 一样不约束
- **cdc 假违例处理**:cmos→merge 格雷码跨域路径补互异步时钟组(原设计 core_clk 无约束从未检查)
- **构建结果:0 错误,全时钟域 WNS 最紧 +3.0ns,TNS=0;全流程 5m37s(精简前约 25 分钟,提速 ~4.5 倍)**
- 产物:`ov5640_sfp480p_test\hdmi_ddr_ov5640_top_slim_rev32.sbit`(2026-09-29 15:45)
- 恢复显示链:搜索 `[SLIM Rev3.2]` 标记逐处取消注释(top.v/fdc/build.tcl)
