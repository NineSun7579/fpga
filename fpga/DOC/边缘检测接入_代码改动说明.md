## 一、这次修的是什么（HDMI 输出完全不对的根因）

上一版边缘流能写进 DDR（实测 252 种不同字节值），但**显示完全错乱**，根因是两个几何错误叠加：

### 错误 1：sobel/align16 的有效像素映射错乱（致命）
原 `ready` 判据用的是 `ccol`（回绕映射的中心列）：
```verilog
wire ready = (pix_cnt >= 2W+3) && (ccol >= 1) && (ccol <= W-2);
```
其中 `ccol = (col>=2) ? col-2 : (col + W - 2)`。当 `col=0` 时 `ccol = W-2`，**落在有效区间内** → 每行第一个周期的输入其实对应上一行的最后一列，被当成有效像素输出。

后果：每行输出长度不均匀，整帧有效像素 **304963** 个；而 `cam_prep_link` 期望 `(W-2)*(H-2) = 304964` 个 → `opix` 永远达不到 `frame_pixels` → **帧永不收尾**（`oactive` 一直为 1）→ 只有第一帧以错误长度写入 → 画面彻底错乱。

### 错误 2：内容尺寸与显示尺寸不匹配
即使帧能收尾，sobel/align16 只输出内部 638×478 像素，而 camview 按 640×480 读 → 逐行漂移。

### 修法：改为「全帧 1:1 输出」
两个模块现在**对每个输入像素都输出一拍**，只在 3×3 窗口完全落在帧内时才判边（`win_ok`），出界位置输出黑（无边）：
```verilog
wire win_ok = (row >= 12'd2) && (col >= 2'd2);   // 窗口中心=(row-1,col-2) 需完整
wire ready  = 1'b1;                              // 恒输出
...
m_valid <= s_valid;                              // 1:1，不再按 ready 丢弃
m_edge  <= win_ok && (mag >= thr_edge);          // 出界不判边
```
好处：行宽恒为 W、无剪切、无逐行漂移；`frame_pixels = W*H` 精确匹配。

## 二、改动文件清单（共 5 个 RTL + 1 个应用）

| 文件 | 改动 |
|---|---|
| `source/preprocess/sobel_edge.v` | 新增 `row` 计数；`win_ok` 门控判边；`ready=1` 恒输出；`m_valid<=s_valid` 全帧 1:1 |
| `source/preprocess/align16.v` | 同上（与 sobel 严格同构，保证两路逐像素对齐）；`row` 计数；`m_valid<=s_valid` |
| `source/preprocess/cam_prep_link.v` | ①RAW tap 解耦：`cam_ready=raw_ready`(恒1)、`raw_data=cam_data`、`raw_valid=cam_valid` —— **处理链再慢也不反压相机**（这是当初 preprocess 被旁路的真正原因）；②`frame_pixels = img_width*FRAME_H`（原为 `(W-2)*(H-2)`）；③`opix >= frame_pixels` 容错比较 |
| `source/top.v` | 恢复 `cam_prep_link`/`preprocess_top` 例化（纯 tap 接法，`raw_*` 端口留空、`raw_ready=1'b1`）；删除 5 条 `prep_wr_*` 绑零；`MAX_WIDTH` 1920→**640**（行缓冲是真实寄存器，1920 宽把时序打崩：WNS -0.275ns → 640 后 All Constraints Met +0.961ns）；`FRAME_H=480`、`BUFFER0=0x0A000000`、`BUFFER1=0x0A100000` |
| `source/preprocess/prep_regs.v` | 默认 `r_mode=2'd3`（纯边缘：白边黑底）；默认分辨率 640×480 |
| `host/camview/main.cpp` | **E 键** 边缘/原图切换；默认显示边缘缓冲 `0x0A000000/0x0A100000`；热循环零寄存器访问（避免楔死）；E 切换时才写一次 `prep_regs+0x100` |

**RAW 通路未改动**：`assign cam_s_data = cam_tap_data;` 等 4 行直连保持原样，RAW 帧仍写 `0x00800000/0x00A00000`。

## 三、帧长三方一致性（已验算）

| 项 | 值 |
|---|---|
| 分辨率 | 640×480 = 307,200 像素 |
| tap 输入 | `img_width*FRAME_H/8` = 38,400 字/帧 |
| sobel/align16 输出 | 1:1 全帧 = 307,200 像素（修改后）|
| `cam_prep_link` frame_pixels | `img_width*FRAME_H` = 307,200（修改后）|
| 写引擎 cmd_len | 38,400 字 × 16 = 614,400 字节 |
| camview 读 | 640×480×2 = 614,400 字节 ✓ |

307200 能被 8 整除 → `ocnt` 在帧尾恰好归零 → 无需 partial flush，帧干净收尾。

## 五、验证要点

1. **默认即边缘**：camview 启动后直接读 `0x0A000000/0x0A100000`，显示白边黑底边缘图，左上角约 1 行 1 列为黑（窗口出界不判边，属正常）。
2. **按 E 切换**：边缘 ↔ 原图（原图即 RAW 640×480）。
3. **画面几何应正确**：无逐行斜移、无右侧竖条、无上下错行。
4. **RAW 不受影响**：RAW 缓冲仍是正常相机画面。
5. 若边缘太少（暗场），调低阈值：写 `prep_regs +0x104` 的 `thr_edge`（默认 128，可试 40~60）。
