## 1. 目标链路

```
FMC 双目 OV5640（各 1280×720 RGB565，独立 SCCB）
  → cam1: cmos1_* (Set A) / cam2: cmos2_* (Set B)
  → 各自 ping-pong DDR3（+ FRTAG 帧序号）
  → crossbar M00（cam1=S01, cam2=S04）
  → PCIe Gen2 x2（主机按地址 F2H 读两路）
  → RK3568 camview：左右并排合成 2560×720 → X11 → HDMI
```

## 2. FPGA RTL 改动

| 文件 | 改动 |
|---|---|
| `source/top.v` | 端口新增 `cmos2_*`；`ov5640_top` 例化两次（cam1 默认基址 0x2000_0000，cam2 `BASE_ADDR=0x2000_0200`）；新增第二个 `axi_dma_write`（`cmd_id=4'b0100`）→ crossbar **S04**；`M00_CONNECT_WRITE` 由 `7'b0001111`→`7'b0011111`（放行 S04） |
| `source/ov5640/ovreg_axil_decode.v` | 2 路→**3 路**译码，`addr[9:8]`：`00`=cam1 寄存器、`01`=prep_regs、`10`=cam2 寄存器（`11` 回落 prep，兼容旧路由） |
| `source/ov5640/ov5640_top.v` | 默认分辨率改 720p（`H_CMOS_DISP=1280 / V_CMOS_DISP=720 / TOTAL_H_PIXEL=1892 / TOTAL_V_PIXEL=1300`）；新增参数 `CAM_ADDR_1_DEF/CAM_ADDR_2_DEF` 并下传 |
| `source/ov5640/ov5640_reg.v` | 乒乓默认地址参数化（`CAM_ADDR_1_DEF/CAM_ADDR_2_DEF`），cam2 用 0x00C0_0000/0x00E0_0000 |

- cam2 的 `xdma_irq` 不接（MSI 维持关闭，沿用 DDR tag 判帧，避免历史 MSI 风暴）。
- cam2 不走 `cam_prep_link/preprocess` tap，RAW 直连 S04。
- `CAM_DATA_LEN = 1280*720*2/16 = 115200`（16B/word），帧长 `0x1C2000`。

## 3. 地址 / 寄存器映射

### DDR（FPGA 视角）
| 区域 | 地址 | 说明 |
|---|---|---|
| cam1 ping | `0x0080_0000` | 帧 0x1C2000，tag 在 `+0x1C2000` |
| cam1 pong | `0x00A0_0000` | 同上 |
| cam2 ping | `0x00C0_0000` | 同上 |
| cam2 pong | `0x00E0_0000` | 同上 |

### 寄存器（M01 窗，经 AXI 地址访问）
cam2 寄存器窗基址 **`0x2000_0200`**（相对偏移与 cam1 完全一致）：

| 偏移 | 名称 | 说明 |
|---|---|---|
| `+0x00` | CAM2_ACK | 写 1<<buf 释放该缓冲 |
| `+0x40` | CAM2_EN | bit0 使能（复位默认 1） |
| `+0x80` | CAM2_ADDR_1 | ping 基址（默认 0x00C0_0000） |
| `+0xC0` | CAM2_ADDR_2 | pong 基址（默认 0x00E0_0000） |
| `+0x30/34/38/3C/44/48/4C` | CAM2 dbg | 同 cam1 语义（读不可靠，建议只用 DDR tag） |

> 注：M01 寄存器**读**存在既有缺陷（返回上一次值），本设计全程只写不读，状态用 DDR tag 判定。

## 6. 上板验证步骤

```bash
# 1) JTAG 烧录（每次烧录后必须）
taskkill /F /IM cdt_js.exe   # PC 侧，重开 jtag server
# cdt_cfg 下载 generate_bitstream/top.sbit

# 2) PERST + PCIe 重扫（否则 DMA 静默死锁）
echo 0 > /sys/class/gpio/gpio144/value; sleep 0.3; echo 1 > /sys/class/gpio/gpio144/value
echo 1 > /sys/bus/pci/devices/0002:21:00.0/remove; sleep 1; echo 1 > /sys/bus/pci/rescan

# 3) 驱动
rmmod pango_pci_driver 2>/dev/null; insmod /root/ov5640/pango_pci_driver.ko

# 4) camview（双路并排）
cd /root/ov5640/camview && DISPLAY=:0 XAUTHORITY=/var/run/lightdm/root/:0 ./camview
```

判据：
1. 两路 DDR 帧在动（tag 递增 / 画面刷新）。
2. 若只有 cam1 有图 → cam2 引脚/接线待查（见 §7-2）。
3. 画面噪点/位偏 → 调 IODELAY（见 §7-1）。

## 7. 已知风险与调优旋钮

1. **720p DVP 采样窗（最高优先）**
   - 传感器寄存器序列**未改**（`ov5640_i2c_rgb565_cfg.v` 仍为 0x3035=0x11/0x3036=0x3c/0x3824=0x02），仅把输出尺寸改 1280×720、HTS/VTS=1892/1300。
   - `ov5640_top.v:133` `IODELAY_STEP`（当前 40，两路各一份）**必须在新分辨率下重调**：噪点/位偏时按 0/10/20/40/60 扫描。
   - 若帧率/带宽异常，可调 `TOTAL_H/V_PIXEL` 或 PLL（`0x3036`：0x5A=72MHz / 0x5F / 0x64），改后同步更新 `clock.fdc` 的 cmos pclk 周期。
2. **cam2 引脚来源**：`cmos2_*` 取自 `ov5640.fdc` 中被注释的厂商表（与 cmos1 引脚不重叠）。若上板 cam2 无数据，优先核对 FMC 实际走线。
3. **STA-3011（clk_50m 域）**：`free_clk`(V4/LVCMOS15) 经 `assign clk_50m = free_clk` 供两路 SCCB；PDS 对 cam2 i2c FSM 报 "no clock"（cam1 无）。25MHz + 慢速 I2C，功能上无碍（cam1 同源已验证）。曾尝试为 cam2 加 `GTP_CLKBUFG`，导致两路都被报该警告，已回退。
4. **M00 多写主竞争**：cam1(S01)+prep(S03)+cam2(S04) 并发写，依赖既有 mcdq SID 配对 FIFO；上板长时间运行观察撕裂/丢帧。
5. **M01 寄存器读不可靠**：状态判定一律走 DDR tag。

| 项 | 结果 |
|---|---|

**结论**：主机/传输/显示链路与 cam2 正常；问题定位在 **cam1 的 DVP 采样（引脚 Set A）**。
source/ov5640/ov5640_top.v 的 IODELAY_STEP 已提升为**模块参数**，	op.v 中 cam1 可单独覆盖
（当前 .IODELAY_STEP(8'd40)），便于不改动其他逻辑地做扫描。

**下一步建议（按性价比排序）**：
1. **交叉换位**：把两个摄像头模块在 FMC 两个接口间对调。若故障跟着模块走 → 摄像头/排线问题；若仍固定在 Set A → FPGA 引脚/布线/IODELAY 问题。（2 分钟，最能定性）
2. 若判定为采样问题：扫描 cam1 的 IODELAY_STEP（0/20/60/80/120/160…），单值一轮 ≈6 分钟。
3. 复测可用 dualcam_chk.py（读两路 DDR 统计：distinct / 行跳变 / mean / FRTAG）。
