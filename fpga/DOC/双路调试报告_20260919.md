# OV5640 双路输出调试报告 — 2026-09-19 通宵会话

目标：双路 640×480 无条纹不卡顿（截止 09:00）。**未完全达成**：复位后双路帧
真实、完整、无条纹地写入 DDR 并可被主机读取；但 DDR 写通路在持续负载下
2~15 秒内楔死（基础设施级 bug，未根除）。本报告记录已验证的修复、根因链、
遗留问题与下一步方向。

## 一、已修复并验证的 bug（ModelSim 双路 TB 全 PASS + 上板证据）

### 1. 帧完成双账本（条纹+顿挫的直接根因之一）
- 原设计：帧完成判据 = `ov5640_ddr_w.v` 的计数器版 `axi_data_last`，计数器被
  vsync 脉冲清零；vsync 到来时尾部 beat 尚在 FIFO 中 → 完成信号永不触发 →
  FSM 卡 DATA → 0.16s 看门狗 abort → 零 beat 填尾 + 残留错位 → 条纹。
- 修复 `[LEDGER]`：帧完成统一由 DMA 侧 `len` 账本驱动（`axi_dma_write.data_in_last`
  = trans 下降沿脉冲，经 `dma_done`/`frame_done`（DATA 态门控）送入 w_ctrl）。
  涉及：axi_dma_write.v / ov5640_ddr_w_ctrl.v / ov5640_ddr.v / ov5640_top.v / top.v。
- 上板证据：复位后 tag 1/2 正确落 DDR（0x96000 偏移），ping-pong 正确。

### 2. 看门狗预算跨状态泄漏（tag 被静默跳过）
- `wd_cnt` 只在 IDLE 清零 → 慢帧（DMA 收尾 >0.15s）耗尽预算后，紧随的
  ADDR_TAG/DATA_TAG 立即超时 → tag 从不落地。
- 修复 `[WDFIX]`：状态切换沿清零 wd_cnt。上板证据：修复后 tag 立即恢复落地。

### 3. 传感器配置表 PLL 方案错误（"卡住/无帧"的根因）
- 9-17 起改的 "24M-XCLK" 表与板上实际时钟不符：实测 PCLK≈14MHz（既非 56
  也非 84），ISP 不出图，vsync_raw=0，两颗传感器全哑。
- 修复 `[PLLRESTORE]`：时钟/AEC 寄存器恢复 9-16 已验证值（0x3034=18/0x3035=11/
  0x3036=3C/0x4837=22/0x3A02=17 等），9-17 后新增的 11 个杂项寄存器（含只读
  ID 寄存器 0x3002/0x3006）改为无害重复写。**修复后两路 vsync 32Hz、PCLK≈60MHz，
  帧数据真实写入 DDR（暗场景 0x0020 像素、zdin≈17k 零字/帧吻合）。**

### 4. ddr_fifo16_w AW 水位门控方向写反
- `awlen < wr_water_level`，而 water_level=占用数：16 拍突发只在 FIFO **全满**
  时放行（恰好是丢数据的时刻），空时反而禁止。
- 修复 `[WATERFIX]`：改为空闲数门控 `awlen < (16 - wr_water_level)`。
- 此 bug 是"16 拍突发必丢 W beat → DDR3 IP 永远收不齐 awlen+1 拍 → 永不发 B"
  的机制解释（即 9-18 [WD2] "cam2 bvalid never asserted" 的根源）。

### 5. 杂项
- cam2 CAM_EN_DEF 0→1；camview 1280×720→640×480；camview 盲乒乓改 tag 驱动；
  ioctl 3 次重试+8s 超时（抗 MSI 等待抖动）；`ips2l_pcie_dma_ram_Reset_Value.v`
  （无人引用的死文件）包同名空 module 使纯 Verilog 合法（PDS 对它 W/E 不定）。

## 二、遗留问题（未根除，今晚多轮实验定位到现象级）

**现象**：复位/驱动重载后，双路帧真实流动（数据+tag 正确）；2~15 秒后
M00 写通路（crossbar→ddr_fifo16_w→DDR3 用户口）永久楔死：B 停止返回、
AW 停止受理、主机读 DDR 仍正常。仅 JTAG 重配置或驱动重载可复活。

**已试配置**（均楔死，存活时间不同）：BURST_LEN=1/8/16；WATERFIX 前后；
pending 门控/ACKLESS/IDLEGATE（FSM 空闲门控）；bwatch B 快超时（10µs 强制
收尾——该改动本身会破坏在途事务，已回退）。

**证据链**：
- 楔死后 cam_words 计数仍狂涨（打包 FIFO 满）、FSM 停 ADDR/DATA、aw_cnt/b_cnt
  停在个位数（首突发后即死）。
- M01 寄存器写（H2F ACK/EN）与高频描述符操作会显著提前楔死（协议文档记载的
  axi_to_axi_lite 桥缺陷）；纯读会话可稳定 25~60s。
- 9-16 "可用"基线实为单路（备份 top.v 中 cam2/S04 未接 crossbar），双路并发
  写从未在此板上稳定工作过。

**下一步方向**（按嫌疑排序）：
1. 在 ModelSim 中搭 crossbar+ddr_fifo16_w+DDR3 用户口模型的最小复现台架，
   重放双相机并发写+主机读负载（今晚 TB 缺这一层，故仿真全过而上板楔死）。
2. 检查 axi_crossbar_7x3 的 B 通路路由表在多主并发下的状态机（Forencich
   开源核，可读源码 axi_crossbar_wr.v:520+）。
3. ddr_fifo16_w 只有 16 深（每项 1 beat）且 wr_en 无 full 保护：考虑换 64+ 深
   FIFO 或给 W 通路加 almost_full 握手。
4. DDR3 用户口（PDS ipcore，保护勿动）的 outstanding write 上限与 B 生成
   条件需用逻辑分析仪/ILA 确认。

## 五、追加（09-19 08:10，第二阶段）

**发现并修复第三层根因：AW/AR 分裂握手（已上板验证 PCIe 正常，但未根治写楔死）**

读 top.v DDR3 端口区发现结构缺陷：
1. crossbar 的 `m00_axi_awready` **直连** DDR3 IP 的 awready，而 awvalid 走水位门控寄存器。
   门控关闭时若 IP 空闲拉高 awready，crossbar 侧完成握手并放行 W beat，**IP 从未见过
   该 AW**→孤儿 W beat 永远凑不齐 `wusero_last`→fabric 侧伪造的 B（top.v:414 按
   W 末拍铸造）永不产生→DMA 永久卡死。
2. 门控寄存器每周期重求值=**可撤回已置起的 valid**（AXI 违规）。
3. AR 侧同构缺陷（`arvalid & fifo_empty` 可撤回）——解释主机 F2H 读楔死。
4. B 为 fabric 伪造（IP 无 B 输出端口），bid 靠单个 aw_sid 寄存器重建——多笔在途时
   sid 被覆盖、B 错路由（ddrtest 的 16B 交换错位与此吻合）。

修复 `[AWFIX/ARFIX]`（top.v）：AW/AR 各加锁存-保持垫片——crossbar 仅在锁存时刻收到
ready；请求保持（AXI 合法）直到 IP 接受；AW 侧全链路单笔在途（无在途 AW + W FIFO
空 + 无未决 B 才锁存），AR 侧要求 R FIFO 空——sid 重建恒正确。

**结果**：编译通过（pclk_div2 域残留 -0.162ns/3 端点 hold 违例，布线器 6 轮未能修，
实测 PCIe 起链正常判定为余量内）；上板后写通路楔死仍未根治（未观测窗口内发生），
但主机读通路存活时间从 ~15s 延长到 40-50s。**判断：还存在至少一层未定位的机制**
（怀疑方向：DDR3 IP 内部写命令队列与 fabric 侧 W/FIFO 消费的配对、或 crossbar 写
通道状态机）。下一步建议不变：搭 crossbar+FIFO+IP 行为模型的仿真台架做信号级复现。

## 八、最终解决（09-19 上午，全部完成 ✅）

### 写通路楔死 —— 根因与修复
**根因**：开源 axi_crossbar 的 M00 写通道在多主连续交接时泄漏其每主 W 通道
选择寄存器（台架逐拍实证：`w_select_valid_reg` 冻结在上一笔的 S01，S04 的 W 拍
永不放行，两引擎同时饿死）。这是楔死的最后一块拼图，与板上"1-2 笔突发后
永久死亡"逐拍吻合。

**修复 [WARB]**：新模块 `source/axi_crossbar/ddr_w_arb.v`（2 主单笔在途轮询
仲裁器，85 行）替代 crossbar 的 M00 写通道。crossbar 保留主机读（M00 读）、
寄存器（M01）与主机写 DDR（S00 写）。S01/S04 的 crossbar 写端口退役。

**验证**：
- 台架 `sim/wedge/tb_wedge.v`：连续双流 4ms、**9741 笔突发全部完成、零楔死** PASS
  （修复前 2 笔即死）
- 上板：**50 秒持续 19.5 fps / 19.5 fps，fails=0**（近 2000 帧）——修复前
  1-2 帧后永久死亡
- camview 稳定运行 **13 fps** 连续显示

### 帧数据零块条纹（屏幕竖条纹）—— 根因与修复
**根因**：DDR 帧内容出现 **8 拍数据 + 8 拍全零**的周期块。引擎侧零拍计数
（zdin/zout=0）证明零不在数据流里；零来自 **DDR3 IP 读空 FIFO**：IP 的 W 通道
不可节流（自走 wready、自计 awlen+1 拍），而 BURST_LEN=8 时 staging 只需 8 拍
即放行 AW，IP 消费完 8 拍后继续要第 9-16 拍时 FIFO 已空 → 空拍被当零数据写入。

**修复 [ZEROFIX]**：`BURST_LEN = 16`（= IP 最大 awlen+1 = FIFO 深度 16）。
staging 门控随之变为"FIFO 满才呈现 AW"，IP 消费整个突发期间 FIFO 只减不增、
绝无空拍——构造性免疫。

**验证**：板上 DDR 内容 **零拍 0/80**（修复前 32/80，80 拍/扫描行），
四张连续截图：**双路并排实时画面、零条纹、零撕裂、帧间内容变化**（活流）。
