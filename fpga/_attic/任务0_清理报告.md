## 二、判定方法（穷举交叉验证）

结论不依赖计划清单，四个独立证据全部一致才归档：

1. **编译证据**：`project/compile/run.log` 显示 PDS 实际 `.rtl_analyze` 仅 162/187 个
   登记文件；`conv_weight_all.v`、`conv11_weight_all.v` 从未被单独编译（后被
   include 检查证实也不是 include 目标，PDS 导航器"Include files"分类系误标）。
2. **字节级 + 去注释双重可达性分析**（`_attic/reachability_check.py`）：从顶层 `top`
   正向遍历例化图；GBK 编码文件下 git bash grep 会**静默漏匹配**（实测
   `sync_fifo_D.v` 中纯 ASCII 的 `fifo_ram_D #(` grep 查不到），因此所有 token
   匹配在原始字节上做，假阳性只会导致"少归档"，方向安全。
3. **`include` 全量交叉检查**：全工程仅 7 类 include（config.v、defines.v、
   ips2l_pcie_dma_ram_init_param.v 及 ipcore 自带），28 个归档目标无一被 include。
4. **PDS GUI 状态佐证**：Sources 树中 9 个死文件列于异常分组，与静态分析一致。
